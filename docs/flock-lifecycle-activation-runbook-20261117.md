# 鸡群生命周期接续与运行手册

本功能代码发布与真实业务激活分别验收。没有真实盘点、责任人、证据及差异签认，不批准任何旧群接续；不以初始数差额补造死亡，不猜品种、群号或历史日期。

## 权限与附件准备

系统管理员在鸡群生命周期页注册角色动作项，再通过现有角色权限配置分别授予：制单/提交`MENU_FLOCK_CREATE:E`、独立审核`MENU_FLOCK_APPROVE:A`、过账`MENU_FLOCK_POST:E`；基线、盘点、冲销、日报更正补录、关闭、清舍和历史期间授权另需相应`MENU_FLOCK_*:A`。所有操作还需`MENU_FARM_DATA:V`及真实养殖数据范围。注册不自动授权业务角色，制单与审核必须不同用户。

附件使用统一上传组件，绑定鸡舍、公司/场区、制单人。不存在、PENDING、已禁用、删除或跨舍/公司/制单人的文件均不能作为证据；审核人使用单据的受控附件预览。文件仅证明业务依据已保存，真实盘点和现场签认仍由业务负责。

## 只读历史诊断与阻断清单

在经授权的本机脱敏副本运行`scripts/ops/flock-lifecycle-diagnostic.cjs`，仅显式读取`FLOCK_DIAGNOSTIC_PG_URL`，不读项目.env，不连接生产。输出每个检查的NO_FINDINGS、REVIEW_REQUIRED或BLOCKED_SCHEMA；缺表不得称通过。任何修正另走专项受控脚本/单据及回执。

阻断项：一舍多在栏、群舍农场/公司不符、非零退役、负数/小数/空余额、未知品种/状态/开始日期、旧淘汰日期含义未定、日报ALL/DAILY与班次混用、快照断链、来源档案缺失/重叠、旧FARM_IN/补账/生产包装销售数量待核对。计划淘汰字段为planned_elimination_date；elimination_date历史值保留，未核实不能当实际结束。

每个群填写并留存：

| 字段 | 真实签认内容 |
|---|---|
| 公司/农场/鸡舍/鸡群 | 以权威档案核对，不新编历史身份 |
| 基线日 | 盘点当天；基线是该日盘点时点的批准余额 |
| 实盘数量 | 现场实际羽数，与系统旧余额分列 |
| 责任人和复核人 | 两个实际人员，复核不能由制单人替代 |
| 证据附件 | 实盘/交接/差异处理材料的受控文件 |
| 差异及处置 | 每项真实原因和处理回执，不把未知差额写成死亡 |
| 来源与日期 | 遗传品种标准码、商业来源有效期及旧淘汰日期含义 |
| 下游核对 | 日报、包装、已入库、销售和待补账是否对齐 |

BASELINE过账前重新校验旧余额、唯一在栏、标准品种、容量、基线后无旧日报；没有基线的历史群保持P0保护。接续基线当天旧日报只读，次日开始只用一舍日DAILY汇总，不与班次重复扣减。新空舍在生命周期看板显示「新空舍」。先用「办理清洗消毒」登记实际清洗，再用「办理清舍验收」上传现场依据，分别提交、审核并过账。状态变为「可入栏」后，办理正式入栏单生成群号和占栏。整群转入同样要求目标舍已验收。之前在未验收时创建的原单，若保存的鸡舍版本与验收后版本不同，由有权人员取消，再按原实物交接依据及实际业务日期重新制单审核。

## 现场操作

- 入栏：选来源类型。外购选ACTIVE供应商；内部育成选同公司有授权农场。填写真实交接单号/日龄/数量、上传凭据，独立审核过账。交接来源唯一，不能换一个自动幂等号重复入栏。已经在事件账内的群转舍用TRANSFER，不用新入栏冒充部分调鸡。
- 死亡：实际发生日、数量、原因、处置方式、接收人和证据。日报显示事件汇总，不能再手填不同死淘数。
- 淘汰：实际移出产蛋群才扣存栏，同时建立实际待售安置位置余额。客户交付仅扣此待售余额，须客户、币种、单价、签收及凭据；形成PENDING_FINANCE结算依据，不表示已开应收或已收款。财务按ERP自有销售依据审核，严禁接好业财到业务发票。
- 整群转舍：同公司、目标空舍且已清舍验收、双方均有授权，整群数量守恒。转舍业务日期须晚于来源舍的占栏开始日（历史实盘基线日、正式入栏日或上次转入日），并且不得早于最近已过账事件。页面显示该日期下限；按实物发生日制单。实际盘点与转舍确实同日时，保留原始单据和交接凭证交生产主管专项核对。转舍日及其后来源舍、目标舍已有日报时须先核对生产归属。需要运输在途时不得用瞬时转舍假装两地同时在栏。
- 免疫计划跟随群：原计划位置和实际执行位置分别保留；未完计划在现占栏执行。用药保留当时位置、疗程和休药期，未来开始日属于计划，不提前扣药。用药/休药期鸡蛋不能走普通产蛋入库，须兽医隔离处置。
- 关闭：先确认最后一天DAILY日报，或选真实零产蛋签认并上传依据；任何旧班次/重复/身份不符日报均HOLD核对，零签认不能与非零记录矛盾。余额归零、未完生命周期/免疫单据及疗程/休药处理完毕；保留旧占栏和来源。清舍开始、验收与设施ACTIVE/停用分别管理；旧群关闭当天的来源仍属于旧群，下一批不得同日入栏。
- 盘点/更正：另开有依据的盘点调整单；已过账用反向事件及替代事件，不改删旧事实。已关闭群可在总量仍零且真实待售去向可核对时更正分类，不能凭空恢复在栏。跨月授权必须由真实已审核过账的HISTORY_AUTH绑定本单来源和受影响原日期。

## 日报确认与历史更正/补录

首次已接续DAILY提交即确认实际日报，普通新增/upsert/PUT仅接受同值重试。更正进入生命周期的“历史日报更正与补录”，选择真实原占栏日报；缺记录选“所选业务日缺日报·独立审批补录”，须有当日有效占栏，未知旧来源保持HOLD。分级按启用主数据填写，实际料水未知留空，不自动造0；明确实测零才填0。

原值快照、原占栏及批准改值随单保留，审核期间原日报或余额版本变化需重制。跨月必须先创建待更正单，再开历史授权绑定该来源、原日期和群舍；独立审核过账授权后，才能过账更正单。已接收来源检查历史累计处理量，不能只看剩余库存；多来源/继承数量无精确分配时禁止猜等级更正，先处理下游库存并核对差异。更正不自动补库存或消除已售产蛋。

关闭后不普通补录。原零产蛋签认若经调查需更正，批准补录单自动保存原CLOSE ID/声明哈希及差异回执，原单反向显示更正；群仍为关闭、在栏余额仍零，真实历史来源保持原位置。死亡/淘汰数量使用REVERSE替代事件，不能写日报来恢复数量。

## 产蛋、库存及追溯

商业SKU继续由已批准来源档案决定，遗传品种只用于生物追溯。激活舍日具有稳定日报ID和占栏ID；同一来源首次入库路径被认领后不能从另一入口再入账，切换库存模式也不解除认领。旧库存幂等重放不补猜新群。

包装多来源保留实际分级投入明细；RELATED_INPUT明确表示投入关联，allocated_output_qty为空，不伪称逐群输出已精确分摊。调拨/子批与退货继承来源关系；销售FIFO仍按原批次。未接续旧批次显示UNVERIFIED_LEGACY，不查询当前舍群来补成历史来源。

## 发布、停写与回退

只用现有受控CI/CD发布，生产不手工DDL/DML。迁移为空安装可down，任何草稿、审核、事件、占栏、认领、健康活动或结算事实/引用均拒绝自动删除。回退须停写并核备份；已启用后优先兼容前进修复，不回旧代码继续手改存栏。

本次运行基线与配置floor不同，顺序为重新inspect且审计GO → 新鲜备份及恢复性验证 → 受控应用实际8条待迁移并保存回执 → API-only重锚定F/R/T → API正式SUCCESS且OPEN后对同T做Web-only。不能改为一次full，也不能以run_migrations=false绕过schema应用回执。API失败不切Web，Web失败保留正式PREPARED状态并按既有流程核对；完整abort未在隔离测试中执行，不能宣称已演练。详见`docs/ops/flock-descendant-floor-reanchor-20261117.md`。

发布回执必须记录候选SHA、CI结果、备份和回退核验、真实运行SHA、迁移状态、健康和关键冒烟。两家公司各自试点需真实操作及盘点签认；若缺少这些，代码可受控发布但旧群保持未激活，不能宣称试点完成。

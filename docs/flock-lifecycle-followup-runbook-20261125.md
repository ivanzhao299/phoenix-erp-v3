# 鸡群生命周期后续交付与批修手册

## 待售交付和实收

在已过账交付原单中，有公司财务应收查看权限的人可查看实收。具备财务编辑权限的人员核对签收凭据、原币金额和既有入账，再生成专属 ERP 应收。已知相同交付或签收引用的既有应收须先核对。专属单号以交付 UUID 绑定，重复请求返回同一张应收。原结算凭据保留。

每笔收款按原币等额核销到一张交付应收，支持多笔部分收款。确认后同时存在分摊及资金入账流水才计为实收。财务审批角色填写依据后可冲销该笔收款，系统沿原资金账户追加出账，回转应收余额并保留原分摊。资金不足、账户停用或身份变化时先核对。此入口处理同原币收款，历史手工凭据与跨币种收款交由财务核对。

## 曾经缺少的正式班次

从「盘点与更正」进入日报更正，选择历史占栏和业务日。页面只提供已启用正式分班且恰缺一个班次的舍日。选择缺班后按现场凭证录入真实分级、料水和备注，保存草稿，再为该草稿申请当期签发的历史授权。授权覆盖原业务日，绑定同一张草稿，由具备权限的独立审核人审核，由过账人办理。

过账创建原业务日及原占栏的一行正式班次。其他班次、事件死淘及库存单据沿原有流程。整日没报仍使用原整日补录。当月缺班走普通分班日报入口。关闭日已有已过账关群声明时，先核对声明依据。

## 历史缓存核对和执行

1. 确认公司、鸡舍及业务日期范围。每批最多 100 个鸡舍、366 天区间，以及 5,000 条差异。范围文件使用 `company`、`houses`、`from`、`through` 四个字段。分批以公司、鸡舍及业务日期组织。
2. 使用受控环境中构建的 API 版本，给只读计划进程注入 `FLOCK_CACHE_DATABASE_URL`。保留执行版本、范围文件和计划结果。计划在只读事务中列出缓存原值、应有值、占栏、来源摘要、受阻原因及计划摘要。公司或鸡舍不匹配时终止。
3. 核对并批准该计划的摘要和差异。授权申请及回执需绑定实际环境和版本。实盘基线历史、正式启用前归档、关闭的入库记账期、冻结盘点和在途日报更正保留原值。对在途更正，业务人员可以先按已审批的取消及重制流程处理，再重新生成计划。
4. 在受控执行环境用已批准摘要运行 `apply`。执行按鸡舍及期间串行，在锁内重读计划。摘要变化或任意一行对账失败时整批回滚。保留提交后的已更新 ID 和受阻条数，再运行一次只读计划核查。
5. 同日转舍场景验收 A 舍转出前已过账的死亡仍归 A，B 舍日报缓存只保留 B 舍已过账的损失，群内存栏和 BI 净死淘保持一致。抽查料水、分级、日报身份、原更正快照、过账事件和结算凭据。

```bash
node apps/api/dist/tools/flock-loss-cache-repair.js plan /controlled/approved-scope.json
node apps/api/dist/tools/flock-loss-cache-repair.js apply /controlled/approved-scope.json "$APPROVED_PLAN_SHA256"
```

现金关联和补班以审批接口执行。缓存批修使用受控执行环境、精确范围和计划摘要。代码部署与生产批修分别留存回执。

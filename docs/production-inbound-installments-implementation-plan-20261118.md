# 正式分次生产入库最终执行方案

2026-11-18 · 供开发、测试、业务和发布负责人共同审查。已采纳业务决定：历史产蛋日报、关联的历史测试入库可以作为测试资料保留，无需精准迁移和恢复。本文是执行方案，实施与上线另行记录。

## 1. 推荐决策及范围

沿用现有两家公司、鸡舍、仓库和 SKU。按“公司＋鸡舍”选择首个完整的新加坡产蛋业务日，从该日起记录正式业务。正式期间支持同一鸡舍同一日分多次交库。先在一舍完成真实交库与下游核验，再扩到另一公司及其余鸡舍。新建账套仅作原环境无法隔离测试影响时的备选。

| 原方案工作 | 最终处置 |
|---|---|
| 还原孟赛 47,930 枚的提交过程、逐笔重建 8 批、对四级和五级各 30 枚作实账冲销 | 移出上线范围。日报、批次、流水保留为历史测试资料；截图数值只在隔离测试环境复现。60 枚不冲，差额不补 |
| 历史入库基线导入器、旧流水与来源逐笔配对、历史补记审批和专案执行包 | 从分次入库开发清单移除。已有候选代码中的专案 apply 入口退役或在归档范围永久拒绝，旧审计证据可查 |
| 鸡群接续、现场实物期初、商业来源以及在途占用 | 按切换现场的真实状态确认。鸡群只按盘点接续一次，库存期初只在确有实物时建立 |
| 正式期间分次、重试、冲销、日报更正及来源追溯 | 完整实施。新正式单的错误仍要按原凭证审批更正 |
| 全库历史数据及财务、订单、药品等其他业务 | 本方案只处置本次产蛋链路的测试范围。关联对象须识别测试与真实用途，保留其他业务的原账和权限 |

复核基线为 origin/main 的 a7c0045b 和草稿 PR #574 的 6422bdc4。该候选通过的 CI 属于此前鸡群生命周期工作。历史原因与采证边界见[事故复核](daily-inbound-conflict-incident-review-20261118.md)，鸡群接续见[启用手册](flock-lifecycle-activation-runbook-20261117.md)。原事故报告的恢复建议由本版第 1、2 节取代。

## 2. 切换日、历史隔离与期初

1. **冻结切换范围。** 每公司每鸡舍登记第一正式产蛋日、实际启用时刻、业务时区、归属仓、当前鸡群、品种、商业蛋品来源、确认人和版本。切点选尚无测试或真实作业交错的完整生产日。迟到写入、离线重发、后台补单同时校验生产日和来源资格。昨天生产的测试蛋今天提交仍归历史；仅凭日期、创建时间、批号前缀无法认定正式资格。
2. **保留测试资料，封闭写入口。** 用只读盘点生成版本化范围清单，记录公司、鸡舍、旧日报/批次及可以影响正式业务的子批、未结预占、包装在制、调拨在途、订单或财务引用。无需核清各批曾入多少或重演每张历史单。旧单只在带标识的历史视图查询。按旧日报或其键重试、导入旧记录、旧终端离线重传、通用建批或专案脚本均不得生成正式事实。
3. **正式库存按有效来源准入。** 在启用范围保存切换版本和批次资格。受控的正式生产、获批实盘期初、合法采购/其他既有正式入口均按真实来源认定。调拨、包装、拆分/合并须传递来源资格，测试或来源不明的批次不能经子批、退货、撤销预占或改变库存状态变成正式批次。保留库存状态字典的既有含义。查询、按单号/批号直写、自动分配和后台任务都适用；库存、估值、财务接口、BI 和导出与正式明细用同一范围。共享仓只能隔离涉蛋范围，不能屏蔽同仓其他公司的合法库存或其他品类。
4. **按现场确定期初。** 无实物且无有效在途或预占的范围可零开账。有实物则按公司、仓位、蛋种、等级、数量、可用/受限状态、生产日/效期和成本确认一张库存期初单，走统一库存接口，记录独立来源、盘点证据与唯一交接编号。原测试库存先退出正式视图，期初只登记一次。期初不占新日报额度，不算当日产量，不伪造历史鸡群链。未达到效期、质检、成本或来源要求的用途保持受限。成本未知不得默认为已核定的零成本。跨鸡舍共享仓按实物盘点边界统一去重，不让两舍各认一份。
5. **处理跨界引用。** 确为测试的在途任务在正式流程中冻结或归档。若旧批次挂有真实待发订单、真实预占或外部凭证，仅核实这条依赖，按已有业务流程接续或换绑并核对余额。归属待定时暂停受影响批次、仓库或鸡舍，其余能证明隔离的范围可先行。测试认定无需清库、改旧单、批量置零或冲财务账。
6. **确认启用。** 停止并排空受影响的旧写入，在同一切换版本内复核库存范围、在途、期初交接与主数据、落实各副本的持久开关。只有指定范围通过验收才开放新单。每个新正式舍日从有效生产过账量零开始；实物期初在库存侧单列。

## 3. 正式账规则与鸡群来源

- 按公司、鸡舍、产蛋日、等级，以枚为基础单位。逐级可入量 = 已确认日报量 − 正式正向过账量 ＋ 已批准且已过账的原入库冲销量。单行必须是可入范围内的正整数。零数量不建批。不同 SKU、规格、批次和仓库共享同一等级额度。每个时点应满足 0 ≤ 有效过账 ≤ 日报量，异常须阻断并显示明细。
- 销售、调拨、包装损耗、退货和盘点各走自己的库存流水，对生产额度没有增减作用。按单查回执始终返回原数量；页面分别列出日报量、有效已入、可入余额和现存量。日报 1,000，先入 100、卖 40、再入 900，累计已入 1,000、库存 960，重试首单仍返回 100。
- 鸡舍按产蛋日解析当时有效的鸡群、占栏和商业蛋品来源。生物品种、普通/粉壳/红壳商品类别、鸡蛋等级分别建模。一个群死亡或淘汰按已审核事件变动存栏，更换群时先关闭旧占栏再开新占栏。既有来源和回执保留原快照。真实期初鸡数、品种及商品映射由现场确认。
- 日报更正与入库使用同一依据及锁。同一日汇总和班次报表不得重复覆盖。支持有依据的多班分配，数量分摊与实物追溯分别表达。只在原料、占栏和交接可证时记精确来源；无法满足该产品追溯条件时停止过账。
- TEMP 临时入库与直接包装保留舍日路径互斥，避免同一批蛋分别从两条路径进库存。包装有自身原料收量约束。已登记销售、转仓、包装、质检或关账的正式原单，冲销前核查实物、下游和财务状态；占用未解除或补偿依据不足时阻断。只有已过账的原入库冲销能释放对应额度。

**单据和事务约定**

1. 一次实物交接对应一张正式单。客户端持久保存创建意图，多个操作者通过共同交接号找回原单。有正式交接号时按公司和交接来源做唯一校验。数量相同的两次独立交接可以分别入库。
2. DRAFT 支持带版本编辑，READY 冻结摘要、提交键、日报依据、仓位及预期记账日，不预占额度。POSTED 表示已提交。未过账单可以取消。超时先查原单；同键同内容返回原回执，同键改内容返回 409 且无副作用。已成功单跨日可查，未过账冻结单跨新加坡记账日须重新确认。生产日与效期仍按实物确定。
3. 所有入口遵守相同锁序：鸡舍、舍日控制及依据、单据，再按既有顺序锁库存资源。锁内重新验证切换范围、资格、额度和数据权限。同一事务写所有档的批次、库存流水、单行、分配、来源及回执，任一档失败则本单整体回滚。单头 POSTED 在提交后才对外可见。POSTED 重试只校验查看权和原键/摘要，不重新要求旧 SKU 仍启用。
4. 新单号作为批次 source_no 和流水引用，生产日、鸡舍另存。现有 TEMP 唯一索引含单号、SKU、等级和规格，保留其数据库防重能力。相同单内若匹配同一索引维度，冻结前合并同质行或明确拒绝；一行可分到多份日报依据。不同正式单允许同日、同档、同 SKU 分次过账。
5. 各正向分配保存原行、真实日报 ID/版本、分配量及原来源 receipt/link。按单行和分配生成唯一来源键，保留原始事实。冲销逐段引用原分配，锁内校验累计上限，补偿事实同时抵减正式额度与对应来源。TEMP 收量及精确来源是同一次投入的不同视图，不可重复加减；子批继承也不重复释放额度。
6. 旧 DAILY 键只查询有据可查的历史回执。无原回执则提示“测试期记录已归档，请在正式期间新建交库单”。旧入口不能把旧草稿、已售空批次或零库存重建为正式库存。新旧页面部署间隙由服务端拒绝不兼容写入。

## 6. 合并、部署和试点

1. **开发合并。** 在隔离分支按工作包追加提交，以 origin/main 复核。沿用草稿 PR #574 统一集成，清理或锁死专案执行入口，范围变化后重跑最终提交的相关测试、迁移演练和必需 CI。合入 main 时业务开关默认关闭，以实际合并版本构建并核验 API/Web 镜像。
2. **先验证现有迁移准入。** 发布前刷新线上实际版本、配置版本、待迁移全集及其摘要、备份和旧服务兼容性。现有迁移流程在有待执行迁移时检查业务审计 GO，已存在的后台状态文件必须为 OPEN。保留全库结构检查，尤其是建唯一索引要求的实际全表无重复。把旧数据认定为测试，本身不会改变自动检查的输出。
3. **处理审计和准入顺序。** 优先走现有受控流程。若旧业务差异使其保持 HOLD，保存原始报告；在不依赖待建新表的前提下，以已冻结范围清单和只读事实验证隔离，把仅涉已确认测试数据的业务差异单列。全库结构冲突、未隔离风险和正式业务异常继续阻断。只有相应准入路径已实现、演练并获发布审查，才可采用；不能过滤旧行伪造原审计 GO。若普通路径仍不可用，沿用已设计的专门维护流程作为备选。
4. **维护路径的条件。** 在同一受控维护会话核对原配置、实际运行版、目标版及迁移摘要。先围住所有相关 HTTP 写入口并排空在途和后台，再做带访问保护、摘要和可解析性验证的新备份，以目标迁移镜像执行获准结构变更。迁移前检查与 API 晋级前的真实已应用回执分开。维护租约、写入围栏、旧版兼容或备份无有效证据即停止。结构完成单独留回执。
5. **部署、启用。** 先发 API 并验证真实版本、健康、权限、旧写入口封闭和后台恢复，再发同一版本 Web。两次部署分别取得实际回执，期间新功能保持关闭。现场执行第 2 节的切换盘点，逐范围验证并启用。先在首个鸡舍以真实交库完成两次分次入库、查回执和下游核对；按真实业务节奏验收，不在生产构造数量。选择另一公司不同商品来源的鸡舍交叉验证后扩围。
6. **观察与回退。** 监控正式范围内重复入库数、超额度数、账实/来源差异、测试批被正式选择数、未知来源、超时未判定单。出现重复、串账或越权时关闭受影响范围新写入并保留查询，保存失败快照并核对已提交单。未产生正式事实时仅回退至与新结构/版本下限兼容的已验证版本；已有期初或正式单后优先向前修复，禁止重开旧写入口、自动降库或自动恢复旧备份。只有实际部署和试点验收后才登记发布版本与标签。

**现场交付物**包括范围与切换日清单、盘点/零期初确认、真实在途处置结果、隔离验收、最终提交和镜像标识、结构变更回执、API/Web 发布回执、试点首两单及复核记录。孟赛旧案恢复回执不在交付清单。

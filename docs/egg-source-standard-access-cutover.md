# 蛋品来源档案标准权限和生产切换

角色和权限集显示同一个蛋品来源菜单。管理员在该行选择 V、C、E 和 A，然后预览账号和鸡舍的有效权限变化并填写依据。D 和 X 当前禁用。用户管理负责配置实际养殖组织。角色继承的动作和直授动作分开显示。旧单办理区域继续使用 V1 的原仓及原动作。

首次转换沿用原动作和每项动作的原范围。旧单舍或分动作限制仍参与授权。已转换主体清空动作即撤权，旧范围只作为保留限制与审计。后续编辑显示各限制内保存前后的动作。一个全新的角色或权限集按账号实际养殖组织授权，普通账号使用有效公司、场站或显式农场绑定。操作要求同一鸡舍具备查看权及所需动作。

## 生产发布

1. 在实际业务范围逐舍按全部状态和全部分页清点。由原申请人取消确认的 V1 测试草稿或待审单，或由独立审核人按现有规则驳回测试待审单。保留原号、操作结果和真实在途。应用结果待核时先查回执。
2. 清点并完成旧单操作后，在来源总写入控制暂停写入，确认在途事务排空。普通数据审计保留原结论。本次仅允许经过批准的单项结构迁移专项。
3. 使用 `egg-source-standard-1127` 独立检查同一正式候选、账本、备份条件和当前权威范围。应用前后持续暂停来源总写入。受控迁移回执确认旧授权和门禁保留且新版标准配置为空。
4. 用同一提交成对发布 API 与 Web，核对 OCI 和健康回执，确认旧实例已退出。权限转换可在写入暂停时执行。逐主体预览、保存、重登，以实际账号、鸡舍和原仓核对。保留旧仓授权和显式拒绝，处理需人工核定的范围。
5. 恢复来源写入和新版写入。按真实业务清单逐舍开通或登记暂停。确认两个实际普通账号分别有 V/C/E 和 V/A，并由两人完成首笔真实新版申请的提交与独立审批。
6. 确认证据后才永久关闭 V1 新建。已有 V1 单仍按原权限和原仓办理。逐舍暂停只停止该舍新建，全局新版暂停可同时冻结所有 V2 写操作，总写入暂停影响两版。

受控应用已提交但回执缺失时，用原检查、应用运行、备份和账本恢复，禁止重复执行 DDL。存在新版标准配置时，保留兼容代码及迁移结构，故障按影响范围暂停并前向处理。

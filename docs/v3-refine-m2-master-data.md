## 抓到并修的问题

### 🔴 G124 — DataScope 不认 sys_user_orgs 绑定的 GROUP 范围
- **现象**：部门绑定 + 显式授 GROUP 范围的人（郭大鹏/刘杰/刘汉涛/王乐金/范镇豪）看空公司级主数据（客户/项目/资金账户=0）。
- **根因**：`DataScopeService.resolve` 的 `isGlobal` 只看 `sys_data_scopes` 角色规则，忽略 G114 给用户绑定显式设的 `data_scope_level='GROUP'`。角色无 GROUP 规则 → 非全局 + 部门展开无公司 → DENY。
- **修**：`userOrgRows` 查出后，任一绑定 `data_scope_level='GROUP'` → 视为全局（绑定的 GROUP 是权威 per-user 授权）。

### 🔴 G125 — SITE/DEPT 节点 company_code=null，范围未向上卷到所属公司
- **现象**：场站级维护人（宋守江=孟赛场仓储经理）看空仓库主数据（0），而公司级维护人（薛峰）正常（7）。
- **根因**：SITE 组织节点 `company_code` 为 null（path=`/ORG-GROUP/COMP-LAO-AGRI/SITE-MENGSAI-LAYER/`），DataScope 只把它加进 siteCodes，公司维度空 → 仓库主数据（**只有公司维度、无 site 列**）被 DENY。
- **修**：DataScope 对 `company_code=null` 的节点**向上回溯**（RECURSIVE up）到最近 COMPANY 祖先，加入公司范围。与既有"向下穿透"（BU/集团→子公司）互补。
- **为何安全**：仓库/客户/供应商主数据本身只到公司粒度；菜单权限是第一道闸（宋守江只有仓库主数据菜单，DataScope 仅在已授权类型内做行过滤），上卷不会越权看到无菜单的类型。

### 🟡 M2-1 — 主数据页裸错误码
- 无权类型被 URL 直达时页面甩 `MENU_PERMISSION_DENIED`。已加 `friendlyError()`：403→「您没有「XX」的访问权限，请联系系统管理员」，401/网络同样译中文。

## ② 关键字段审批：G92 → G93 架构演进（非 bug）
- G92 的"关键字段人工审批队列"**已被 G93「自动审批」取代**：主数据字段编辑走**自动校验网关**（查重/必填/格式/值域/引用），全过即时落库、不过当场抛错退回（中文原因）。`keyFields`/`pendingChange` 为 G92 遗留、仅兼容前端。
- **实测网关健康**：
  - 改 credit_limit=99999（值合法）→ 即时生效 ✓
  - 改 customer_name 为已存在名 → 拦下「客户名称…已存在（编码 CUS-MS-R-015），不可重复」✓
  - 清空必填 company_code → 拦下「必填项归属公司不能为空」✓
- **遗留决策**：财务敏感字段（授信额度 credit_limit / 账期 payment_terms）当前值合法即即时生效、无人工签核。是否需保留人工复核 → 待业务确认（影响 M3 财务模块）。

## 教训沉淀
G114/G115 治理把"用户↔组织"绑定设对了，但**行级数据范围的实际驱动有多条旧链路没跟着认新绑定**：
1. `sys_user.store_code`（generic-crud 行级过滤实际驱动）— G122 同步
2. `DataScope` 的 isGlobal 只认角色规则 — G124 补认绑定 GROUP
3. `DataScope` 公司维度对 SITE/DEPT 不上卷 — G125 补向上回溯

这三条纯看代码发现不了，**必须 impersonate 逐角色实测**才暴露。

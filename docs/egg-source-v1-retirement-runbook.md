# 蛋品来源档案 V1 清理与 V2 切换

技术发布提供 SITE 授权修复、V1 测试单归档、旧版权限定向撤回和 V2 双岗切换核验。管理员在 ERP 核定鸡舍、正式办理账号和归档清单。两位办理人可以用本人账号完成切换核验，也可使用一张真实的 V2 独立审批单作为业务验收依据。

## 发布窗口

1. 记录 API、Web 版本和两个来源开关。在维护窗口于角色与权限打开「蛋品来源总写入」，填写原因并暂停总写入。冻结来源权限及逐舍配置，直到迁移回执核验完成。
2. Controlled pending migration apply 选择 egg-source-retirement-1127。先做 inspect，确认唯一待迁移项为 1795658900000-EggSourceCutoverEvidence，并下载回执。对同一提交发起 apply，传入检查运行号、账本及检查摘要和获批指令。流程校验备份后增加空表并复核账本、目录和生产证据。
3. 在同一提交运行 Deploy 的 full 模式，启用生产批准与保留备份，关闭重复迁移。复核 API、Web 运行版本和公网健康，按窗口恢复原来源总写入状态。
4. 使用双岗非业务核验时，在 Egg source cutover release evidence 填入上述 full 部署运行号并启用安装。流程用已发布镜像、独立 PostgreSQL 和 Chromium 作验收。凭证绑定两端镜像摘要、部署尝试和验收运行。任一端替换后，旧凭证失效。验收凭证有效期为 12 小时，双岗核验最多 30 分钟。

## 确定鸡舍和账号

1. 在「系统设置中心 → 角色与权限 → 蛋品来源档案动作配置」核对申请角色 V/C/E，审核角色 V/A。账号的公司、农场、场站或鸡舍范围来自现有组织设置。场站范围从有效上级公司及唯一有效农场核定。
2. 在「蛋品来源鸡舍开通」选择实际鸡舍并填入两个实名账号，逐人核对有效动作和授权来源。修正组织断链、归属冲突、多农场映射或显式拒绝。总写入和新版写入均可用后，登记开通已就绪鸡舍。其他适用鸡舍逐舍登记暂停。
3. 两位办理人分别用本人账号重新登录。申请人在「主数据中心 → 蛋品来源档案」选择同一舍，确认有「新建来源变更」，新版表单按鸡舍办理。审核人确认可以访问本舍并拥有独立审核资格。

## 处置旧单与关闭 V1

1. 在「旧版测试单与授权清理」核对 V1 记录、原申请号、鸡舍和下游证据。申请人取消在途测试申请，或者由独立审核人驳回。保留曾审批、已生成来源档、有关联库存或生产单据的原记录。
2. 在暂停窗口，选择已核实的测试单，填写可追溯依据，确认归档。归档在日常列表隐藏原单。按原申请号可查明细和原回执。按操作请求号可查归档、恢复和撤权回执。发现新证据时可恢复原单可见性。
3. 恢复总写入，保持新版写入开放。完成一张真实的 V2 独立审批，或从「旧版新建入口」发起双岗退役核验，两位办理人打开同一个链接，核对鸡舍、档期和版本后分别确认。管理员刷新核验结果，再关闭旧版新建。双岗核验只生成上线记录。V1 关闸后禁止重新开启。
4. 确认 V1 无未终结申请，再短暂停用总写入，按角色或权限集撤回已复核的 V1 正向动作。逐项核对旧仓、原范围、显式拒绝、关联账户和留证读取。撤回后恢复总写入，检查新版日常办理及旧版留证查询。
5. 操作响应中断时，先按原请求号查回执。在页面保留原请求时可以原号重试。授权、业务档期或开关变化时，刷新后重新核对。

## 异常处置

- 迁移后发生核验或部署失败，保留受控备份和回执，按同一检查运行的恢复规则处理。产生归档或签署证据后，迁移回退会拒绝删表。
- 双岗确认失效，由管理员重新发起，或使用已完成的真实 V2 独立审批。V1 关闭后如需暂缓新版，可在新版总开关或逐舍开通页暂停。

# 生产管理优化交付核查

基线 `b80d326812b011966b3d98580ad001e20ac1acb2`。开发在独立工作树 `codex/production-management-ui-api` 进行，生产发布以受控工作流验证的提交为准。

| 范围 | 当前候选变更 | 放行前核查 |
| --- | --- | --- |
| 正式交库与旧临时入库 | 按服务端已保存版本冻结，按交接号跨日查回原单，冻结响应中断可认回。旧入库按原始流水核回执，与现存量分列。 | 最终候选重跑正式、旧式及切换场景。 |
| 日报与总览 | 区分全部分级、可售产蛋和缺测，补旧手机的独立汇总契约。历史按舍、日、班查询并续页，总览按业务日和日末占栏聚合。 | 旧手机可明确提交零产蛋，逐舍显示回执或待核并只重试未确认项。放行前核对浏览器验收以及日报、BI 和导出的勾稽。 |
| 养殖档案、卫生和环境 | 鸡舍普通编辑保留状态，鸡舍与鸡群支持服务端筛选和续页，清洗验收可带出原过账单标识。告警读取失败、数据不全及未分级单列提示。 | 鸡舍登记的持久防重、启停单列、清洗原单导航，告警完整分页及前态动作检查、盘点分页和移动可访问性验收。 |
| 药品与历史蛋源 | 本人原意图与逐行入库回执在原事务内绑定。历史核认可按原键恢复，选择有明确归属的停用舍，并提示待他人审核。 | 两端丢响应、账号切换、旧客户端兼容及不同授权仓实测。 |
| 饲料账 | 新账键为公司、农场和业务日。仓储发放读取已过账 WMS 发放单的业务日与批次流水。现场耗用和盘余按物料及原单位单独记账，保存按版本整单提交。历史读保持授权限制，未证实归属的原行保留。 | 原账经业务方确认均为测试数据，保留原值，免做历史归属对账。核对原单业务日口径和跨公司单据；指定首场及切换日期，验证旧写入口兼容或围栏，再签认退役。软件默认保留原客户端合同，新账可分场只读核对。受控配置填 `公司编码/农场编码` 时仅允许该场试点登记，试点账用于比对，现行台账仍是正式账。全量切换经签认后配置 `*`，届时旧写入口返回 409。生产 Compose 保持已批准配置版本，试点配置需单独受控晋升；当前接线仅用于 staging。 |

已在隔离 PostgreSQL 18 执行正式交库浏览器、旧入库原量回放、旧手机日报、鸡舍鸡群分页、药品并发和饲料跨场及整单原子性验证。具体最终运行以 CI 同一提交的结果为准。

发布需绑定同一 main SHA，先按 `ordinary` 审核受控迁移名单，逐条核对申请、回执和零待执行迁移，再切换 API 与 Web。迁移为 `1795565100000`、`1795565200000`、`1795565300000`。软件发布与饲料首场实账启用分别签认。

# Production 95 Cleanup Batch - DR Restore Drill

Date: 2026-07-01

## Objective

Close the observability/operations debt item "backup exists, but restore has not been rehearsed." The goal is to prove that a Phoenix ERP backup artifact can be restored into an isolated scratch database and queried, without touching production.

## Scope

Executed a local isolated disaster-recovery drill:

- Source database: local `phoenix_erp`.
- Backup format: PostgreSQL custom dump.
- Restore target: one-time scratch database generated by `scripts/dr-rehearsal.sh`.
- Migration forward-run: skipped in this drill using `RUN_MIGRATIONS=no`; this round only proves backup restoreability.
- Production DB: not touched.
- Remote server: not touched.

## Findings During Drill

The drill found two real platform issues before passing:

1. `pg_dump` version mismatch.
   - Homebrew `pg_dump` was 16.14 while local Postgres.app server was 18.3.
   - The drill was rerun with `/Applications/Postgres.app/Contents/Versions/latest/bin` prepended to `PATH`.

2. `scripts/dr-rehearsal.sh` had hidden encoding damage around `$SCRATCH_DB`.
   - Bash parsed `$SCRATCH_DB` plus a hidden character as an unbound variable.
   - The script now uses `${SCRATCH_DB}` everywhere to make variable boundaries explicit.

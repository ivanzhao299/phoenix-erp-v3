# Owner-delegated maintenance authority

The project owner's trusted interactive instruction permits delegated COMMENT
review and execution. This mode records `OWNER_DELEGATED` and `AUTHORIZED`;
it never manufactures GitHub APPROVE, reviewer identity or administrator role.
The existing independent GitHub approval path retains its original checks.

The runtime reader accepts only an exact, protected registration at
`maintenance-owner-grant-<run>-<attempt>.json`. Root/trusted paths/original FD9,
private regular-file identity, two pinned reads and directory identity remain
mandatory. Any revocation pathname, including an unreadable or dangling link,
refuses consumption. A missing grant, expired window, changed context, run,
actor, source, artifact, PRE or API-only/HOLD scope refuses admission. The
owner branch does not authorize UNKNOWN_EFFECTS, Web, migration, credential
rotation, automatic rollback or Chanjet synchronization.

This module has no writer, CLI or environment approval switch. A source COMMENT
or a digest supplied by a release plan cannot register runtime permission. The
formal trusted bootstrap must separately verify the real user authorization,
final source/main and server facts, confirmed maintenance window and actual
release/recovery evidence before creating the registration. That bootstrap and
the complete production first-switch factory are not installed by this change.
Production remains HOLD until their actual safety conditions are satisfied.

Local validation: 93 targeted authority/transition/admission/staging checks
passed. The complete maintenance plus bundle suite passed 698 checks, with
28 opt-in native/PG checks skipped and zero failures. These skips are NOT_RUN
for this change, not inherited PASS. The tests use isolated files and synthetic
user grants; they do not register or authorize a production grant. They cover
actual typed admission, protected-record refusal, revocation before STOP,
wrong run/actor/window/scope, and preservation of the old GitHub self-review
rejection. Staging tests found missing import-closure entries; the production
and recovery bundles were completed and re-run before this result.

- 失败请求：`POST /api/v2/finance/expenses/1/submit`
- 失败响应：`APPROVER_NOT_FOUND`，`approverType=ORG_MANAGER`，
  `companyCode=COMP-LAO-AGRI`，`stepNo=1`

## 根因

费用审批规则第一步定义为“申请人所属组织负责人（ORG_MANAGER）”。
审批引擎已经把 `starterUserId` 传入审批人解析上下文，但
`AssignmentResolverService` 未使用该值，只按单据的项目或公司节点查询
`sys_organizations.manager_user_id`。

因此，当申请人的负责人配置在其主组织或上级组织、而公司节点本身没有负责人时，
解析结果为空并返回 HTTP 400。该问题属于审批人解析逻辑缺口，不需要 schema、
entity、迁移或数据写入。

## 修复

`ORG_MANAGER` 解析现在：

1. 优先从发起人的主组织开始，沿组织父链向上查找最近的显式
   `manager_user_id`；
2. 校验该负责人对应 ACTIVE 用户；
3. 若发起人未绑定主组织、组织链没有有效负责人，保留原项目/公司节点负责人回退；
4. 若两条路径均无有效负责人，继续 fail-safe 返回 `APPROVER_NOT_FOUND`。

未增加管理员、角色或任意用户兜底；原有 RBAC、DataScope、审计、附件 ACL
和审批人本人校验均未放宽。

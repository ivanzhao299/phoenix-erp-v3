# WMS 入库、出库与生产领用业务审计

## 1. 审计结论

入库和出库不是“原材料页面”与“鸡蛋页面”的同义词，而是库存数量变化的两类方向。库存品目必须先确定身份，再根据业务来源选择单据类型。

- `MATERIAL`：饲料原料、兽药、包材、设备、配件、工具、办公和其他低值物料，来源为 `mst_materials`。
- `SKU`：可库存的半成品或产成品，来源为 `product_skus`。鸡蛋分级/包装产物属于此类。
- `inv_batches`：唯一可用库存批次事实。
- `inv_ledger`：每次库存增加和减少的不可省略流水。
- `wms_inbound` / `wms_outbound`：业务单据，不可绕过批次与流水直接修改库存。

本轮审计发现的根因是：页面过去把 `item` 当自由文本或 SKU 使用，类型虽有预留但缺少品目类别、去向和成本对象校验；此外仪表盘曾将“枚、kg、件”等不同单位直接相加，形成没有业务意义的库存总量。

## 2. 入库业务边界

| 入库类型 | 可入品目 | 来源/触发 | 核心控制 |
| --- | --- | --- | --- |
| `PURCHASE` 采购入库 | 原材料、饲料、兽药、包材、配件、外购 SKU | 采购收货 | 采购收货与库存入账同事务；物料/SKU 必须为 ACTIVE |
| `PRODUCTION` 生产入库 | 半成品/产成品 SKU | 生产完工、包装入库 | 后端强制 SKU；不可把原材料伪装成生产完工品 |
| `TRANSFER_RECEIVE` 调拨接收 | 沿用源批次品目 | 原子调拨流程 | 不允许手工形成单边调拨；源仓减少与目标仓增加同事务 |
| `RETURN` 退货入库 | 原销售品目 | 销售退货/退库 | 应引用原出库或销售单，保留批次追溯 |
| `ADJUSTMENT` 盘盈入库 | 盘点确认的既有品目 | 盘点差异审批 | 高风险调整，应由盘点流程产生 |
| `OPENING` 期初入库 | 经上线核准的既有品目 | 初始化 | 仅初始化窗口使用，禁止日常业务复用 |

因此，“入库是不是只入原材料、半成品”这个问题的答案是：**不是**。采购可入物料和外购成品，生产入库只入 SKU，调拨和退货沿用原品目身份，期初/盘盈是受控治理动作。

## 3. 出库业务边界

| 出库类型 | 可出品目 | 去向 | 台账类型 |
| --- | --- | --- | --- |
| `SALE` 销售出库 | 可销售 SKU | 客户/门店 | `SALE_OUTBOUND` |
| `PRODUCTION_USE` 生产领用 | 原料、包材或生产过程允许的库存品目 | 鸡舍/部门/项目 | `PRODUCTION_ISSUE` |
| `FEED_DISTRIBUTION` 饲料发放 | `FEED_RAW` 物料 | 鸡舍 | `FEED_ISSUE` |
| `MEDICINE_DISTRIBUTION` 兽药发放 | `VET_DRUG` 物料 | 鸡舍 | `MEDICINE_ISSUE` |
| `LOGISTICS_USE` 后勤领用 | 后勤物料 | 部门/项目/员工 | `LOGISTICS_ISSUE` |
| `SPARE_PART_USE` 配件领用 | 设备、工具、建材、其他配件 | 部门/项目/员工 | `SPARE_PART_ISSUE` |
| `OFFICE_USE` 办公领用 | `OFFICE` 物料 | 部门/员工 | `OFFICE_ISSUE` |
| `MAINTENANCE_USE` 维修领用 | 设备、工具、建材、配件 | 鸡舍/部门/项目 | `MAINTENANCE_ISSUE` |
| `RETURN` 退供出库 | 原采购品目 | 供应商 | `PURCHASE_RETURN_OUT` |
| `SCRAP` 报废出库 | 经批准的库存品目 | 其他/报废 | `SCRAP_OUTBOUND` |

库间调拨不属于普通独立出库。系统已有 `/inventory/transfer/confirm` 原子事务，本轮明确禁止用 `wms_outbound` 独立单据执行 `TRANSFER`，避免只扣源仓而未增加目标仓。

## 4. 入库与出库的逻辑关系

1. 入库确认：单据校验 -> 解析标准品目 -> 写/累加 `inv_batches` -> 写正数 `inv_ledger` -> 单据完成。
2. 出库确认：单据校验 -> 锁定可用批次 -> FIFO 或指定批次扣减 -> 写负数 `inv_ledger` -> 单据完成。
3. 任何确认失败均回滚整个事务，不能出现单据完成但库存未变，或库存变化但无流水。
4. 同一批次必须保持品目、仓库、单位一致；停用、隔离、锁定和过期批次不得继续出库。
5. 不同计量单位不得合计。库存总览按“枚、kg、件、箱”等分别汇总，单据数与库存数量也不得混为一个指标。

库存守恒口径：

```text
期末可用量 = 期初可用量 + 已确认入库 - 已确认出库 +/- 已批准盘点差异
```

## 5. 本轮实施

- 入库选择器统一支持物料主数据与产成品 SKU，禁止新增自由文本库存品目。
- SKU 计量单位从包装规格 `base_unit` 派生，仅在历史规格缺失时回退为“枚”。
- 采购收货可写物料或 SKU 的标准身份、单位和类别。
- 生产入库后端强制标准 SKU。
- 新增生产、饲料、兽药、后勤、配件、办公和维修领用策略。
- 领用单记录公司、项目、部门、员工、鸡舍、用途/工单等成本对象。
- 出库按指定批次或 FIFO 扣减，数量支持三位小数。
- 新增 `MENU_WMS_ISSUE` 原子菜单权限；查看、创建、编辑、删除分别按 `V/C/E/D` 控制。
- 销售出库只能使用 SKU；饲料和兽药按物料类别强校验。
- 库间调拨强制使用既有原子调拨流程。
- 仓库仪表盘取消跨单位“库存总量”，改为批次数和按单位汇总。
- 库存查询展示物料/SKU 身份、物料类别和计量单位。

## 6. 权限与数据域

- 销售、退供和报废等普通出库：`MENU_WMS_INOUT`。
- 生产与内部领用：`MENU_WMS_ISSUE`。
- 管理员、仓储经理拥有完整动作；仓储操作员、场长拥有查看/创建/编辑，不默认拥有删除。
- 仓库写入继续受 `allowedWarehouseCodes` 约束。
- 部门选择器使用 `MENU_WMS_ISSUE` 对应的数据域，不再借用组织主数据编辑权限。
- 后端再次按单据类型检查原子权限，不能只靠前端隐藏按钮。

## 7. 仍需在 UAT 环境验证的真实数据

本机 PostgreSQL 读取受到 Postgres.app 权限确认阻断，本轮没有绕过，也没有执行数据库写入。迁移应用到 UAT 后需核验：

1. `mst_materials` 的物料类型与计量单位完整率。
2. `product_skus` 的 ACTIVE SKU 和成品单位。
3. 历史 `wms_inbound` / `wms_outbound` 自由文本品目的映射率。
4. 历史批次缺失 `unit`、`item_type`、`material_code` 的数量。
5. 仓库、部门、项目、鸡舍和员工数据域是否覆盖真实领用人。

缺失身份的历史批次应进入 `NEED_MAPPING`，不得自动猜测或静默改写。

## 8. 后续长任务

### P0：UAT 数据迁移与回填

- 在 UAT 运行 `1785200000000-AddWmsIssueOutboundGovernance.ts`。
- 只读盘点历史品目和单位缺失，不自动改业务数据。
- 建立历史自由文本到 `mst_materials` / `product_skus` 的人工确认映射。

### P1：生产领料单深化

- 接生产工单/BOM，形成计划用量、已领、退料和超领审批。
- 将领用成本归集到项目、部门、鸡舍和生产批次。
- 建立生产退料，与原领用单和批次反向勾稽。

### P1：后勤与配件治理

- 配件增加序列号/设备关联（适用时）。
- 维修领用关联维修工单，办公领用关联部门/人员。
- 增加领用审批阈值和超额告警。

### P1：饲料/兽药台账收敛

- 对账 `farm_feed`、用药记录与 `inv_ledger`，逐步取消旁路库存写入。
- 饲料发放与鸡舍日耗、兽药发放与用药执行形成一一追溯。

### P2：成本与财务

- 按移动平均/FIFO 形成领用成本。
- 生成财务凭证草稿，保持好业财只读边界，写入仍需单独 Gate。

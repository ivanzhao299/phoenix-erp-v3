> 证据时间：2026-07-30 11:05 CST  
> 权威状态：生产 `GET /api/chanjet/integration/current-state` 及 WMS、资金余额只读端点  
> 当前决策：`HOLD`，下一 Gate 为 `CHANJET_PROVIDER_SCOPE_PERMISSION_REPAIR`  
> 安全边界：本轮未写好业财、未写 ERP 库存/财务业务事实、未执行 migration。

## 1. 结论

好业财已经存在可用的库存、入库、出库和银行/现金余额数据。当前系统已经能把这些数据完整拉到 ERP 的只读中间层并建立规范化文档模型，但尚未达到“直接写入 ERP 唯一库存台账”或“ERP 反向写入好业财”的条件。

不能把历史 2,685 张库存单据直接重放进 ERP，否则可能把现有库存重复增加。正确落地方式是先确定切换时点，以好业财即时库存作为 ERP 期初基线，再从水位点以后按单据增量同步。

银行账户方面，好业财与 ERP 不是同一类模型：

- 好业财 `FIN_ACCOUNT` 是财务账户目录，不是余额权威源。
- 好业财 `GL_BALANCE` 最新期间的 1001/1002 末级科目余额是已记账余额权威源。
- ERP `fin_cash_accounts` 是业务运营账户，余额来自 ERP 收付款流水。
- 双方应映射、对账和展示差异，不应互相静默覆盖。

## 4. 为什么现在不能直接同步入 ERP 库存

### 4.1 历史重放风险

ERP 已有库存台账。如果把好业财历史 2,685 张单据全部再执行一次，会重复增加或扣减库存。必须先确定：

1. 切换时点。
2. 期初库存权威快照。
3. 增量水位点。
4. 已在 ERP 发生过的单据去重规则。

### 4.2 主数据映射仅 8.56%

当前 187 个 WMS 身份中：

| 类型 | 已映射 | 总数 | 覆盖率 |
| --- | ---: | ---: | ---: |
| 仓库 | 0 | 25 | 0% |
| 商品/SKU/物料 | 10 | 134 | 7.46% |
| 单位 | 6 | 28 | 21.43% |
| 合计 | 16 | 187 | 8.56% |

未映射项不能靠名称模糊匹配自动写库存。鸡舍也不能被错误当作仓库；必须建立鸡舍、仓库、库位的归属策略。

### 4.3 业务晋升执行器尚未开放

现有 `promotion candidate` 只保存审核证据，不修改 `inv_batches` / `inv_ledger`。真实晋升必须走 WMS 统一服务，不能直接 SQL 写库存。

## 5. 银行账户：ERP 与好业财差异

| 维度 | ERP | 好业财 | 融合策略 |
| --- | --- | --- | --- |
| 账户模型 | `fin_cash_accounts`，业务运营账户 | `FIN_ACCOUNT`，财务账户目录 | 建立稳定映射，不互相覆盖 |
| 余额来源 | ERP 收付款流水汇总 | `GL_BALANCE` 已记账总账余额 | 好业财作财务主口径，ERP作业务辅助口径 |
| 账户数量 | 42 个 ACTIVE 账户 | 49 条账户目录；31 条现金/银行末级余额行 | 先解释一对多，再补齐 12 个 source-only 映射 |
| 已确认映射 | 不适用 | 37/49 | 覆盖率 75.51% |
| 币种 | CNY/LAK/THB/USD 原币余额 | 原币余额 + CNY 本位币余额 | 按币种比较；集团卡片显示本位币 |
| 状态 | ACTIVE/FROZEN 等运营状态 | 科目/账户启用和记账状态 | 两种状态分别保存，不互相翻译覆盖 |
| 银行信息 | 银行名、账号、账户名、公司 | 财务目录与科目辅助信息 | 账号脱敏匹配，名称仅作辅助 |
| 交易明细 | ERP 单据和现金流水 | 好业财凭证、收付款单和总账 | 单据对账，不从余额反推明细 |
| 写入方向 | 产生经审批的业务单据/凭证草稿 | 接收已批准财务凭证或收付款单 | 不允许直接写余额 |

## 7. 银行账户双端同步目标模型

| 数据域 | 权威源 | 入 ERP | 出好业财 |
| --- | --- | --- | --- |
| 已记账银行/现金余额 | 好业财 GL | 只读快照与财务卡片 | 禁止直接写余额 |
| ERP 业务收付款流水 | ERP | ERP 自有业务事实 | 审批后形成收付款/凭证 Outbox |
| 账户目录 | 双方映射治理 | 映射表，不静默新建 | 仅经单独主数据 Gate |
| 凭证 | 好业财为过账权威 | 回读凭证号、状态、期间 | ERP 审核后单笔推送 |
| 汇率/本位币 | 好业财财务口径 | 保存原币与本位币 | 不由 ERP 擅自覆盖 |
| 差异 | 对账中心 | `OK/WARN/MISMATCH/HOLD` | 不自动冲销 |

### P1：主数据映射清账

1. WMS 25 个仓库、134 个商品/物料、28 个单位逐项确定性映射。
2. 建立鸡舍 → ERP 仓库/库位归属，不允许鸡舍名称直接映射仓库。
3. 建立 SKU 包装单位与基础单位换算。
4. 银行账户完成 49 条好业财目录到 ERP 账户的映射，解释 12 条 source-only。
5. 修复 26 条账户目录与总账末级行的关联缺口。

验收：WMS 与银行账户映射均达到 100%，冲突为 0。

### P2：好业财库存期初单向导入 ERP

1. 冻结切换时间和账套/公司/仓库范围。
2. 以好业财即时库存、批次库存生成 ERP 期初库存预览。
3. 进行数量、单位、批次、成本、仓库、库位六维对账。
4. 只选择一个账套、一个仓库做 Canary。
5. 经 WMS 统一服务写入，不使用旁路 SQL。
6. 保存来源账套、接口、单据 ID、行 ID、版本和同步批次。

验收：Canary 数量/批次/成本差异为 0，重复执行不产生重复库存。

### P3：好业财库存增量同步 ERP

1. 从切换水位点以后同步入库、出库、调拨、盘点。
2. 幂等键采用账套 + 接口 + 单据 ID + 版本 + 行 ID。
3. 红字、作废、反审核走反向库存动作，不删除历史。
4. 每日自动对账并生成差异原因。
5. 权限失败进入 HOLD，不无限重试。

验收：连续 7 天无重复入账、无丢单，日终差异为 0 或有明确 HOLD 原因。

### P4：银行账户单向财务对齐

1. 同步账户目录、原币余额、本位币余额和期间。
2. ERP 财务卡片使用好业财权威主值。
3. ERP 业务流水作为辅助明细保留。
4. 按账户、币种、期间对账，不跨币种直接相减。
5. 显示未记账时间差、未映射账户和单据差异。

验收：49/49 账户可解释，集团余额与好业财本位币一致。

### P5：ERP → 好业财写入准备

1. ERP 入库、出库、收款、付款、凭证生成标准 Outbox 草稿。
2. 写前执行主数据、期间、币种、借贷平衡、防重校验。
3. 双人审批后才能进入 `PUSH_READY`。
4. 保存好业财 requestId、回执、外部单号和回读快照。
5. 不允许写余额；只写被好业财官方 API 支持的业务单据。

验收：草稿可重放、防重复，错误进入死信，尚不执行真实外部写入。

### P6：最小双向 Canary 与生产化

1. 每个域仅批准一张低风险单据。
2. 推送后立即从好业财回读，核对所有关键字段。
3. 重复推送必须被幂等拦截。
4. 失败执行补偿或红冲建议，不做破坏性删除。
5. 建立 token 健康、限流、字段漂移、延迟、失败率和差异告警。
6. 通过 A2 安全、A1 CI、A5 数据、A7 最终 Gate 后逐域扩大。

验收：单笔写入、回读、对账、补偿、审计闭环全部通过。

## Diagnosis

Dry-run source review found the current backend already contains the earlier governed-warehouse and payload-normalization repair for this bug, but the medicine stock mutation path still wrote a fixed `inv_ledger` column list after updating `inv_batches`.

That fixed ledger insert can still produce a backend-owned HTTP 500 in environments where optional audit columns such as `log_date`, `warehouse_code`, `company_code`, or `house_code` are absent or lagging the application code. Because inbound and outbound run in one transaction, a ledger insert column error rolls back the stock upsert/deduction, so the user sees a failed submit and the stock overview does not change.


Result: blocked by sandbox socket restriction: `Operation not permitted`. No database writes, migrations, seeds, deploys, pushes, or task-board mutations were performed.

## Changed Files

- `apps/api/src/modules/farm/farm-medicine.service.ts`

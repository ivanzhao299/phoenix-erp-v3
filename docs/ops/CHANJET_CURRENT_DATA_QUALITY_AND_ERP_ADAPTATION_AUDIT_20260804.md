# 好业财当前数据质量与 ERP 适配审计

审计日期：2026-08-04  
审计方式：生产环境只读查询、好业财只读镜像、映射表与同步日志交叉核验  
数据边界：本轮未写好业财、未写 ERP 业务事实、未执行 migration、未部署

## 一、结论先行

好业财目前可以继续作为财务权威来源，但还不能把所有读取结果不加判断地直接写入 ERP。当前主要问题分为四类：

1. **好业财源数据质量问题**：库存存在大量负数；部分公司档案行业、税号和企业性质缺失或错误；往来单位关键字段缺失；少量商品名称、规格和组织维度语义不清。
2. **好业财开放平台问题**：部分已申请功能没有对应 OpenAPI 权限；token 在同步周期内出现集中失效；不同接口刷新时间不一致。
3. **ERP 中间层问题**：部分标准化字段没有从 raw payload 提取；历史对账结果没有在映射修复后自动关闭；旧 AR 快照已过期但仍留在表中。
4. **双方口径适配问题**：库存接口混有仓库明细和无仓库汇总行；客户/供应商编码不是全局唯一；科目同名不等于重复；鸡舍、部门、仓库和成本中心不能用名称直接互换。

按当前证据，整体适配成熟度为 **72/100，GO WITH CONDITIONS**。财务汇总、科目、收付款、主数据镜像可以继续只读使用；库存事实写入、往来余额自动入账和好业财回写必须继续受 Gate 控制。

## 三、P0 问题：必须优先处理

### P0-1 库存出现大面积负数

| 账套 | 库存行 | 负现存量 | 负可用量 |
|---|---:|---:|---:|
| 老挝凤凰农业发展有限公司 | 1,657 | 252（15.21%） | 264（15.93%） |
| 老挝东鹏县星驰农业发展有限公司 | 743 | 113（15.21%） | 104（14.00%） |
| 合计 | 2,400 | 365（15.21%） | 368（15.33%） |

高风险样例包括：

- 星驰冷库“1号粉鸡蛋”：`-2,000,880 枚`。
- 星驰会晒仓库“0号粉蛋”：`-112,171.52 枚`。
- 星驰 1号粮仓“玉米”：`-57,842 斤`。
- 凤凰总库多条鸡蛋商品存在较大负数。

**业务影响**：库存卡片、成本、采购补货、销售可用量和资产金额都会失真。  
**可能根因**：期初库存未完整导入、出库先于入库、重复出库、库存日期/批次口径不一致，或仓库调拨未闭环。  
**财务/仓储要做**：按“账套 + 仓库 + 商品 + 批次 + 日期”核对期初、入库、出库、调拨和盘点。  
**ERP 处理**：负数未解释前只展示来源和风险，不把好业财库存事实提升为 ERP 权威库存，也不把汇总行和仓库行相加。

### P0-2 库存接口混合了不同统计粒度

2,400 条库存行中有 **92 条缺少仓库编码/名称且缺少 `baseOnHandQty`，但存在 `baseAvailQty`**。这类行更像商品汇总或接口总计，不是仓库库存明细。

**风险**：若与仓库明细一起求和，会造成库存卡片重复统计。  
**整改**：中间层增加 `grain_type = WAREHOUSE_DETAIL | PRODUCT_SUMMARY`；无仓库行禁止进入仓库库存台账，只能作为对照汇总。

### P0-3 公司档案基础信息不完整或分类错误

| 账套 | 当前问题 | 建议 |
|---|---|---|
| 老挝凤凰农业发展有限公司 | 行业被标为 `BUILDING_MATERIALS / WHOLESALE_TRADE`；税号、企业性质为空 | 更正为真实农业/养殖行业，补税号和企业性质 |
| 老挝东鹏县星驰农业发展有限公司 | 税号、企业性质为空 | 补齐法定档案并确认本位币、启用期间 |
| 老挝凤凰食品集团有限公司 | 行业为 `ANIMAL_HUSBANDRY`，与食品加工/集团定位可能不一致；税号、企业性质为空 | 财务确认真实主营行业和法人信息 |

三个账套 `baseCurrencyId` 均为 `100001`。考虑到老挝经营和多币种业务，财务需书面确认各账套本位币及汇率政策，ERP 不得跨币种直接求和。

### P0-4 OpenAPI 权限和 token 稳定性不足

- 3 个账套的 `OTHER_STOCK_IN` 与 `RETAIL_STOCK_OUT` 共 6 个读取目标持续返回 `403 / 50111`。
- 商品查询 API `31146` 和商品批量同步 API `19953` 当前应用未获授权；新 token 验证仍返回 `403 / 50111`。
- 最近 24 小时出现 **96 次 `50107 token expired`**，说明自动续期或任务并发换 token 仍不稳定。

**这不是财务源数据问题**，由技术团队和好业财开放平台处理。永久权限 HOLD 不应每轮重试；令牌失效应自动刷新一次并重放只读请求，连续失败后熔断告警。

## 四、P1 问题：影响对账和日常效率

### P1-1 往来单位档案完整度偏低

382 条客户/供应商档案中：

| 字段 | 缺失 | 缺失率 |
|---|---:|---:|
| 税号 | 375 | 98.17% |
| 银行账号 | 381 | 99.74% |
| 法定代表人 | 382 | 100% |
| 地址 | 381 | 99.74% |
| 开票电话 | 382 | 100% |

并非所有个人客户都必须具备上述字段，因此不应全量强制补齐。建议财务先筛选：启用状态、公司型往来单位、发生采购/付款/销售/收款的对象，再补税号、结算账户、地址和开票信息。

### P1-2 客户/供应商编码只能在角色范围内唯一

发现 16 组编码在客户和供应商角色之间复用，例如 `880001` 在不同角色下对应不同名称；同一对象同时是客户和供应商也客观存在。按 `(账套, 角色, 编码)` 查询没有重复。

**结论**：这不是可直接删除的重复数据。ERP 映射键必须使用：

`book_id + party_role_type + source_id`

禁止只按“编码”或“名称”合并，否则会把客户、供应商或双重身份对象串账。

### P1-3 商品名称、规格和编码存在歧义

明确问题：

- `阿莫西林可溶性分`：高置信错别字，建议改为“阿莫西林可溶性粉”；当前写入受商品 API 权限阻断。
- `新谓康`：疑似“新胃康”，需核对包装或采购合同。
- `治梅净`：疑似“治霉净”，需核对包装或采购合同。
- `地美`、`马利克`：名称过短，不可自动改名，必须补通用名/规格/厂家。

同名不同编码且规格为空的疑似重复：

- 凤凰：`台式电子秤`（04042 / 04043）。
- 凤凰：`四系`（0100003 / 01029）。
- 星驰：`氟苯尼考`（0100004 / 366）。

这些项目不能仅凭名称合并。财务/采购应确认是否为不同厂家、含量、包装或历史停用编码；ERP 侧应以 SKU 维度保存“商品 + 规格 + 包装 + 厂家 + UOM”。

### P1-4 部门、鸡舍、仓库和成本中心语义混用

发现的典型问题：

- 食品账套同时存在 `总 部` 与 `总部`。
- 存在部门编码/名称 `50000`，缺乏业务语义。
- “借款”被当作部门，实际更像资金用途或往来性质。
- “鸡舍”和多个编号鸡舍被当作财务部门，实际应区分运营地点、成本中心和组织部门。

**建议**：

- 组织部门：负责人和审批链归属。
- 成本中心：费用和成本归集。
- 鸡舍/场区：生产运营地点。
- 仓库：库存物理位置。

四类主数据可建立映射，但不能合并为同一维度。ERP 应保留多维关联，好业财侧按财务核算需要保留部门/项目辅助核算。

### P1-5 资金账户存在分类和总账勾稽缺口

- 当前资金账户 51 条，其中 22 条缺少账号和开户行。
- 已形成 47 条精确映射、2 条 source-only，映射覆盖率 95.92%。
- 仍有 26 条“资金账户目录 ↔ 总账科目”勾稽缺口。
- 发现名称前导空格：` 琅勃拉邦现金`。

现金、备用金、电子钱包可以没有银行账号；银行账户必须补齐账号、开户行、币种和所属公司。ERP 需要先按账户类型分类，再做完整性检查，不能一刀切。

### P1-6 财务报表和旧快照存在时效差异

- 核心业务端点最近约 4 小时有更新。
- 部分账套的财务报表/凭证最近更新时间为 40–112 小时前。
- 某些主数据原始快照超过 400–700 小时，但整理后的账套表已有更新，说明不同读模型刷新口径不一致。
- 旧 `chanjet_ar_snapshot` 仅 150 行、最近同步为 7 月 5 日；它已经不是当前应收来源。

ERP 必须在每张财务卡片展示“来源账套、数据期间、同步时间、是否过期”，旧 AR 快照只能归档对照，不能继续驱动当前应收数字。

## 五、P2 技术欠账：不应交给财务处理

### P2-1 标准化字段提取不完整

原始 payload 存在，但部分 `chanjet_entity_snapshots` 标准列为空：

- `GL_BALANCE` 353 行中 108 行缺标准编码，4 行缺标准名称。
- `INCOME_STATEMENT` 250 行中 247 行缺标准编码/名称。
- `BALANCE_SHEET` 237 行中 234 行缺标准编码/名称。
- `AR_STATISTICS` 81 行全部缺标准编码。
- `INVENTORY_ON_HAND` 2,400 行的标准 `external_code/name` 未提取。

这是适配器问题，不代表好业财没有数据。技术团队需要按接口版本补 extractor，并以 raw payload 回归测试防字段漂移。

### P2-2 历史对账状态没有随修复自动关闭

当前仍有 1,080 条未关闭对账记录，其中：

- HOLD / HIGH：72。
- WARN / HIGH：925。
- WARN / MEDIUM：83。

其中相当一部分对应的现金账户、部门、项目和仓库映射已修复，但旧记录仍显示未解决。中间层需增加“新一轮对账关闭旧问题”的生命周期，避免管理员和财务看到虚假欠账。

### P2-3 字段映射状态口径陈旧

字段目录仍显示大量 `PENDING`，包括 HIGH 3,615、MEDIUM 220、LOW 102；但近期业务闭环已完成多批确定性映射。说明字段目录、实际 extractor 和业务映射三套状态未收敛。

整改原则：只有影响读取、展示、计算或写入的字段才列为阻断；历史 catalog 项应标记 `NOT_APPLICABLE / SUPERSEDED / MAPPED`，不能长期全部算欠账。

## 六、不能盲目修改的项目

以下现象必须先核对业务上下文，不能自动清理：

1. 同名科目：不同父科目、不同层级下同名可能合法，必须用完整科目路径判断。
2. 客户与供应商复用编码：角色命名空间不同，不等于重复。
3. 同一往来单位同时是客户和供应商：属于合法双重身份。
4. 鸡舍作为辅助核算：可能是成本中心设计，不能直接删除。
5. 现金账户无银行账号：现金、备用金和钱包类可合法为空。
6. 负库存：不能直接回填为零；必须追到期初、单据和批次原因。
7. 商品同名：无规格/厂家证据前不能合并编码。

## 九、双方权威边界建议

| 数据域 | 当前权威来源 | ERP 使用方式 |
|---|---|---|
| 科目、凭证、财务报表、已入账收付款 | 好业财 | 只读镜像和对账 |
| ERP 销售/采购/生产业务单据 | ERP | 业务明细权威，生成财务候选 |
| 应收统计 | 好业财客户级汇总 + ERP 发票级明细 | 并排展示，不互相覆盖 |
| 库存事实 | 暂不单边认定 | 先完成负库存和粒度对账 |
| 客户/供应商财务身份 | 好业财 | 映射到 ERP 主数据，不按名称硬合并 |
| SKU、生产物料、鸡舍/仓位 | ERP | 好业财商品/部门建立映射 |
| 资金余额 | 好业财同币种余额 | ERP 业务流水作为辅助明细 |
| 股东实缴总账 | 好业财 | ERP 保留股东、项目、业务证据和明细 |

特别约束：好业财应收汇总不得写入 `fin_ar_invoices`；发票级账龄、到期日和催收仍由 ERP 业务发票维护。

## 十、建议执行顺序

1. **数据冻结与证据固化**：保留本次快照和负库存清单，不先改数。
2. **源数据清理**：公司档案、商品错名/重复、部门维度、往来单位、资金账户。
3. **开放平台修复**：补 API 权限、token 自动续期、永久 HOLD 熔断。
4. **ERP 适配器修复**：粒度、标准字段、复合身份键、时效标签。
5. **重新全量只读同步**：逐账套核对行数、金额、期间、币种和哈希。
6. **差异对账**：负库存归零或有书面解释；资金、应收、应付、凭证同口径一致。
7. **受控写入试点**：仅对用户明确批准的单条主数据做 canary；事实数据和自动回写继续关闭。

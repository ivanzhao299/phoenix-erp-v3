# 好业财与 Phoenix ERP WMS 同步基线及缺口计划

## 1. 目标与权威边界

同步采用分层权威模型，而不是把两个系统的库存表互相覆盖：

1. 好业财是已生效进销存、财务库存及外部账套数据的只读来源。
2. Phoenix ERP 是养殖、包装、生产领用、后勤领用、配件领用和现场库存动作的业务来源。
3. 好业财数据先进入 ERP 中间层镜像，再做映射和差异对账；不得直接增减 `inv_batches` 或 `inv_ledger`。
4. 两端不一致时显示差异并进入 `NEED_MAPPING`、`MISMATCH` 或 `HOLD`，禁止静默覆盖。
5. 当前只允许好业财到 ERP 的单向读取。ERP 到好业财仅建设数据模型、Outbox、校验和回读能力，不开启外部写入。

## 2. 完整库存只读基线

三个启用账套必须分别覆盖下列 11 类官方接口，共 33 个账套 scope：

| 基线 | 好业财业务 | ERP 用途 | 当前落点 |
| --- | --- | --- | --- |
| `INVENTORY_ON_HAND` | 库存现存量 | 总量、仓库和商品规格余额对账 | 中间层镜像 |
| `INVENTORY_ON_HAND_LOT` | 批次现存量 | 批次、效期、仓库和 SKU 对账 | 中间层镜像 |
| `STOCK_IN` | 采购入库 | ERP 采购入库履约对账 | 中间层 + 标准化预览 |
| `SALES_STOCK_OUT` | 销售出库 | ERP 销售履约对账 | 中间层 + 标准化预览 |
| `FINISHED_GOODS_STOCK_IN` | 产成品入库 | 包装/生产完工入库对账 | 中间层镜像 |
| `MATERIAL_STOCK_OUT` | 材料出库 | 生产领料、饲料、药品耗用对账 | 中间层镜像 |
| `OTHER_STOCK_IN` | 其他入库 | 盘盈、退回、初始化等分类核对 | 中间层镜像 |
| `OTHER_STOCK_OUT` | 其他出库 | 后勤、配件、报废等分类核对 | 中间层镜像 |
| `STOCK_TRANSFER` | 调拨单 | 跨仓移库和在途对账 | 中间层镜像 |
| `STOCK_COUNT` | 盘点单 | 盘盈盘亏和调整依据对账 | 中间层镜像 |
| `RETAIL_STOCK_OUT` | 零售出库 | POS/门店销售出库对账 | 中间层镜像 |

首次同步必须全量分页读取；之后按业务日期窗口增量刷新，并定期做全量校验。空列表是有效证据，但不能证明字段和值已经完整验证。

## 3. 分层同步架构

### L0 原始证据层

- 保存请求 scope、账套、分页、响应 hash、拉取时间和原始响应。
- 不修改字段，不丢未知字段。
- API 响应结构变化必须告警。

### L1 标准化镜像层

- 统一单据号、状态、业务日期、仓库、商品、规格、计量单位、批次、数量、金额、税和源单。
- 保留 `book_id + entity_type + external_id` 幂等身份。
- 红蓝单、作废、审核状态和双计量不得丢失。

### L2 主数据映射层

必须达到以下一一对应基线：

- 好业财账套 ↔ ERP `company_code`
- 好业财仓库 ↔ ERP `warehouse_code`
- 好业财商品/规格 ↔ ERP `product_code` / `sku_code`
- 好业财计量单位 ↔ ERP UOM 字典
- 好业财往来单位 ↔ ERP 客户/供应商
- 好业财部门/项目 ↔ ERP 组织/项目
- 好业财批次 ↔ ERP `batch_no`

名称相同不等于身份相同。自动确认只允许“账套一致 + 编码一致 + 规范化名称一致 + ACTIVE”；模糊匹配必须人工 Gate。

### L3 差异对账层

对账至少覆盖：

1. 好业财现存量 vs ERP `inv_batches` 可用量。
2. 好业财批次现存量 vs ERP 批次、SKU、仓库和状态。
3. 采购入库 vs ERP `PURCHASE` 入库。
4. 销售出库 vs ERP `SALES` 出库。
5. 产成品入库 vs 包装/生产完工入库。
6. 材料出库 vs 生产领料、饲料和药品耗用。
7. 调拨、盘点及其他出入库 vs ERP 对应工作流。

状态固定为 `OK / WARN / MISMATCH / HOLD / NEED_MAPPING / NEED_MANUAL_REVIEW`，并显示数量差、金额差、状态差、缺单和重复单原因。

### L4 ERP 业务促进层

只读镜像不能直接成为 ERP 库存事实。若未来需要把好业财历史单据导入 ERP：

- 先生成 promotion candidate。
- 校验映射、幂等键、状态、红蓝单和库存影响。
- 明确选择“仅历史展示”或“生成 ERP 工作流草稿”。
- 必须单独批准后才可调用 WMS 原子确认服务。
- 已在 ERP 存在的业务单据不得二次形成库存。

### L5 反向同步准备层

ERP 端需要具备能力，但保持禁用：

1. 建立库存专用 Outbox，不能复用凭证 Outbox。
2. 每种单据建立官方写入字段合同和状态机。
3. 使用稳定幂等键、请求 hash、回执、重试、死信和补偿单。
4. 推送前必须通过映射、数量、金额、税、库存和红蓝单校验。
5. 单笔草稿 canary → 人工批准 → 好业财写入 → 立即只读回查。
6. 未获得明确批准时 `externalWriteEnabled=false`。

## 4. P0-P6 固化实施顺序

### P0 数据源完整性

- 部署 11 类只读接口白名单和分页契约。
- 刷新 33 个 scope。
- 输出每个账套每类数据的行数、最新时间、失败原因和字段数量。
- 目标：接口成功率 100%，新鲜度 100%，不允许静默截断。

### P1 字段与标准模型

- 从真实响应生成字段目录和类型。
- 为 9 类新增库存范围补充标准化适配器。
- 建立文档头、明细、余额、批次四种 canonical model。
- 目标：已观测字段分类率 100%，高风险未映射字段为 0。

### P2 主数据映射

- 完成公司、仓库、商品/SKU、单位、批次、客户/供应商、部门、项目映射。
- 建立冲突、重复、源端独有和 ERP 独有清单。
- 目标：参与自动对账的数据映射覆盖率 100%。

### P3 库存差异中心

- 建立按账套、仓库、SKU、批次、日期和业务类型的差异视图。
- 财务与业务卡片显示来源、新鲜度和差异，不混算。
- 目标：每个差异可追到源单和计算口径。

### P4 ERP 历史/业务接入

- 区分历史只读展示、ERP 草稿和 ERP 已确认库存。
- 使用 WMS 服务形成库存，禁止中间层旁路写台账。
- 目标：重复库存写入为 0，所有 promotion 有审批和审计。

### P5 反向同步就绪

- 库存专用 Outbox、幂等、重试、死信、回读和补偿全部实现。
- 完成官方写接口合同审查，但开关继续关闭。
- 目标：在不调用好业财写接口的情况下，单据可通过完整 preflight。

### P6 生产韧性

- 四小时增量、每日全量对账、月末冻结快照。
- token 健康、限流、超时、结构漂移、连续空数据和差异告警。
- 提供手动重跑、单 scope 重跑和断点恢复。
- 目标：同步 SLO 99.5%，失败不丢数、不假成功。

## 5. 当前主要缺口

1. 生产 33 个 scope 已完成受控执行，27 个成功；`OTHER_STOCK_IN` 与 `RETAIL_STOCK_OUT` 在三个账套均被好业财 `50111 openToken无调用该接口的权限` 阻断。
2. 已修复好业财短页导致的静默分页截断，并增加重复页 fail-closed；该规则必须保留为回归门禁。
3. 中间层已有 3,659 个库存实体、2,625 张标准化单据、9,655 条明细；最新成功 API 批次读取 3,490 行。两者口径不同，必须分别展示。
4. ERP 业务列覆盖率 98.1%，仍缺 `wms_outbound.department` 与 `wms_outbound.currency_code`。
5. 9 类新增范围已进入共享标准化合同，但仍需按真实单据逐类锁定字段语义、枚举、红蓝单和双计量规则。
6. 公司、仓库、SKU、UOM、批次、部门、项目和往来单位映射尚未达到自动 promotion 的 100% 基线。
7. 现存量与 ERP `inv_batches`、`inv_ledger` 的自动差异计算尚未实现。
8. 缺少库存专用写回 Outbox；现有凭证 Outbox不可复用。
9. 好业财库存写接口合同、撤销/红冲和回读策略尚未审查，因此反向同步继续 HOLD。
10. 普通用户只能看到融合后的业务数据、来源和差异，不得看到中间层控制台。

## 6. 下一阶段长任务队列

### Gate A：源端权限与 33/33 基线

1. 核准 `OTHER_STOCK_IN` 与 `RETAIL_STOCK_OUT` 的官方应用权限。
2. 权限开通后仅重跑六个失败 scope。
3. 验收：33/33 API 成功，新鲜度 100%，分页无重复、无静默截断。

### Gate B：ERP 字段与 canonical model

1. 为出库补齐部门和币种语义；涉及数据库列时单独走 migration Gate。
2. 为 11 类合同锁定 header、line、balance、lot 四种模型。
3. 建立字段类型、空值、枚举、精度、币种、税率、红蓝单及双计量自动测试。
4. 验收：观测字段分类率 100%，ERP 必需字段覆盖率 100%，未知高风险字段为 0。

### Gate C：主数据身份映射

1. 账套 ↔ 公司。
2. 仓库 ↔ warehouse。
3. 商品/规格 ↔ product/SKU。
4. 单位 ↔ UOM。
5. 批次 ↔ batch。
6. 部门/项目/往来单位 ↔ ERP 主数据。
7. 验收：参与对账记录映射率 100%；模糊、多义、跨账套匹配一律 HOLD。

### Gate D：双台账差异中心

1. 现存量、批次、单据头和明细分别对账。
2. 对采购入库、销售出库、生产/材料、后勤/配件、调拨、盘点建立业务分类。
3. 输出 `OK / WARN / MISMATCH / HOLD / NEED_MAPPING / NEED_MANUAL_REVIEW`。
4. 验收：每项差异可回溯到账套、源单、ERP 单据和计算公式。

### Gate E：ERP 单向接入

1. 先提供只读历史视图。
2. 需要进入 ERP 工作流的数据只生成 promotion candidate。
3. 经审批后调用 WMS service，禁止中间层直接写台账。
4. 验收：幂等、重复库存写入为 0、来源和审批可审计。

### Gate F：反向同步预备

1. 建立库存专用 Outbox、幂等键、请求 hash、回执、重试、死信和补偿。
2. 按 11 类业务形成写入合同和状态机。
3. 建立推送前验证与推送后只读回查。
4. 只做本地 preflight；`externalWriteEnabled` 保持 false。
5. 验收：单据可完整模拟写入、回执和补偿，但不调用好业财写接口。

### Gate G：受控反向 canary 与生产韧性

1. 只有明确批准后允许单笔非破坏性 canary。
2. A2/A1/A7 全部通过后写入并立即回读。
3. 增加四小时增量、每日全量、月末冻结、token、限流、结构漂移和连续空数据告警。
4. 验收：同步 SLO 99.5%，写入可追溯、可补偿，不假成功。

## 7. 验收结论

只读库存基线代码和中间层已经上线，但生产数据完整度为 27/33，因此当前整体结论为 `HOLD`。先完成源端权限和 ERP 两个字段缺口，再按 Gate C-G 逐层关闭映射、对账、ERP promotion 和反向同步缺口。好业财写入仍然禁用。

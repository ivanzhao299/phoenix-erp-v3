# 好业财完整实现长任务计划

更新时间：2026-07-29
实施原则：好业财只读优先，ERP 中间层无损留痕，业务页面按权威口径消费，差异不静默覆盖，任何外部写入必须单独批准。

## 目标状态

1. ERP 可持续读取好业财账套、主数据、财务、报表、收付款、凭证和库存单据。
2. 普通用户无感消费统一业务数据；仅管理员可见中间层治理台。
3. 财务卡片只在权威证据满足时显示好业财口径，并明确数据来源、新鲜度和差异。
4. ERP 与好业财编码通过可审计映射连接，不通过模糊名称猜测。
5. WMS 单据先进入只读镜像和候选区，映射、DataScope、状态和数量口径全部通过后才可申请晋级。
6. 写回只准备草稿、校验、Outbox、幂等、回执和补偿模型；没有明确批准时不暴露执行端点。

## P0 全量只读同步与运行证据

状态：代码完成，运行态 `GO_WITH_CONDITIONS`。

- 读取 29 类当前只读接口契约，其中 1 类为全局账套，28 类按启用账套执行。
- 当前三个启用账套的理论证据目标为 `1 + 28 × 3 = 85`，不再沿用历史静态 `56/56` 作为当前完整口径。
- 所有响应必须通过 HTTP 与业务码双重判定。
- Token 健康检查兼容数组、`data`、`value` 和标准业务响应形态，避免把有效响应误判为失败。
- 供应商 `50111` 权限错误标记为 `PERMISSION_HOLD`，不进入无效重试。
- 只重试网络超时、限流和服务端瞬时错误。
- 定时任务默认不写 ERP 业务镜像；仅显式设置 `CHANJET_ERP_INBOUND_SYNC_ENABLED=true` 才允许进入单向 ERP 会计镜像。

运行条件：

- `OTHER_STOCK_IN`、`RETAIL_STOCK_OUT` 在三个账套共六个 Scope 仍由供应商拒绝。
- Token 到期前必须完成自动续期健康检查。

## P2 主数据和 WMS 业务策略

- 商品 / SKU / 物料

### WMS 硬规则

1. 鸡舍不是仓库，不允许直接建立 `HOUSE -> WAREHOUSE` 映射。
2. 鸡舍型来源必须明确绑定 ERP 鸡舍、真实 WMS 仓库和库位。
3. “箱、桶、包、袋”等单位不得建立脱离商品的全局换算。
4. 包装单位必须绑定来源商品、ERP 商品/SKU/物料、ERP 基础单位和正数换算率。
5. 模糊名称不自动批准。
6. 只保存中间层策略，不修改 ERP 库存事实。

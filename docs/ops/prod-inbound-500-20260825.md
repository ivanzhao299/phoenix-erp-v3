## 2. 根因

`EggInventoryService.createProductionBatch` 的 `inv_batches` INSERT 有 21 个目标列，却有
22 个 VALUES 表达式，并错误引用不存在的 `$18`（实际参数数组只有 17 项）。从
`qty_available` 开始值整体错位，SQL 在执行任何约束检查前即被 PostgreSQL 拒绝。

这是确定性的代码缺陷，与账号、等级、公司或主数据内容无关。

## 3. 修复

- `qty_available` 与 `qty` 都使用 `$12`。
- `status` 固定为 `AVAILABLE`。
- SKU、等级、规格和追溯引用恢复为 `$13` 至 `$17`，与 17 项参数逐一对齐。
- 保持 `ProductionInboundService -> EggInventoryService.createProductionBatch -> inv_ledger`
  的统一入口，未新增库存旁路，FIFO 与台账唯一性不变。
- 新增 SQL 契约回归测试，持续校验目标列数、VALUES 数和最大占位符与参数数一致。

### 7.2 解析链与失败语义

最终链路为：

1. 页面必选 ACTIVE 鸡舍、`EGG_FARM` 仓库和其可用库位；不再接受鸡舍裸文本。
2. 公司优先使用显式值，否则从 ACTIVE `brd_houses.company_code/site_code` 回溯；场站只能在
   唯一归属时回溯。生产正式鸡舍已由 farm 归属下沉这两个字段；遗留空归属鸡舍 fail-fast。
3. 公司必须存在于 ACTIVE `sys_organizations`，并再次执行 company/warehouse DataScope
   断言；非全局用户的 warehouse 不在 `allowedWarehouseCodes` 时拒绝，不放宽语义。
4. 仓库必须属于该公司且为 `ACTIVE + EGG_FARM`；无仓返回 400，多仓要求页面显式选择。
5. 库位必须属于该仓且状态为 `ACTIVE/NORMAL`；无库位返回 400，多库位要求显式选择。
6. SKU 按 `grade + LOOSE` 精确映射，先完整检查所有非零档位，再走
   `createProductionBatch`。该统一入口、FIFO 批号和 ledger 双写均保持不变。

### 7.4 历史修正方案（未执行）

不得对 32 批做一个无条件 UPDATE。建议分两阶段：

1. 仅把 `collection_batch_ref='HOUSE-*'` 且能通过 `brd_houses → brd_farms` 唯一得到公司/场站
   的批次列为候选；`H-DEBUG-A01`、无引用 `...-PROD` 和非 `GRADE_1..5` 行进入人工 HOLD。
2. 业务先确认孟赛实际入库库位（5 个 NORMAL 库位当前没有“默认入库位”标识），再用选定
   `:location_code` 更新 `inv_batches` 和对应 `inv_ledger`；产品映射仅用同等级 ACTIVE
   `LOOSE` SKU。东鹏在补齐 EGG_FARM 仓/库位前不得修正到某个好业财映射仓。

待授权 SQL 应先把候选写入临时映射清单并逐行复核，核心映射形态如下（示意，未执行）：

```sql
-- 先 SELECT 审核；:location_code 必须由业务从真实孟赛入库位中确认。
WITH candidate AS (
  SELECT b.batch_no, f.company_code, 'LPH_MS_EGG_FARM'::text AS warehouse_code,
         :location_code::text AS location_code, s.product_code, s.sku_code,
         s.grade_code, s.spec_code
    FROM inv_batches b
    JOIN brd_houses h ON b.collection_batch_ref = 'HOUSE-' || h.house_code
    JOIN brd_farms f ON f.farm_code = h.farm_code AND f.status = 'ACTIVE'
    JOIN product_skus s ON s.grade_code = b.grade_code_std
                        AND s.spec_code = 'LOOSE' AND s.status = 'ACTIVE'
   WHERE b.source_type = 'TEMP_PRODUCTION'
     AND f.company_code = 'COMP-LAO-AGRI'
)
SELECT * FROM candidate ORDER BY batch_no;
```

正式执行必须在事务内锁定精确 batch_no 清单，断言候选数、SKU 唯一性和 ledger 对应数，再
同步更新 `inv_batches` 与 `inv_ledger` 并做账批一致性复核；本次没有运行任何 UPDATE。

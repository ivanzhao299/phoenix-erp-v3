## 2. 根因

`EggInventoryService.createProductionBatch` 的 `inv_batches` INSERT 有 21 个目标列，却有
22 个 VALUES 表达式，并错误引用不存在的 `$18`（实际参数数组只有 17 项）。从
`qty_available` 开始值整体错位，SQL 在执行任何约束检查前即被 PostgreSQL 拒绝。

这是确定性的代码缺陷，与账号、等级、公司或主数据内容无关。

## 3. 修复

- `qty_available` 与 `qty` 都使用 `$12`。
- `status` 固定为 `AVAILABLE`。
- SKU、等级、规格和追溯引用恢复为 `$13` 至 `$17`，与 17 项参数逐一对齐。
- 保持 `ProductionInboundService -> EggInventoryService.createProductionBatch -> inv_ledger`
  的统一入口，未新增库存旁路，FIFO 与台账唯一性不变。
- 新增 SQL 契约回归测试，持续校验目标列数、VALUES 数和最大占位符与参数数一致。

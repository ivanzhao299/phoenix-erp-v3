# 蛋品来源档案独立授权优化方案（复审修订版）

适用基线为生产及主分支 `24ce3f015e2ba96ecfadbdf1ddf4dc2eb9872428`。本方案解决「角色与权限中找不到独立申请和审核入口」的问题，经独立子代理分别复核权限边界、上线过渡和验收。本文为待审方案，核验范围为已发布源码和流水线记录。生产角色实际授权、截图中原单的当前状态及目标仓登记以现网只读核对为准。 [部署证据](https://github.com/ivanzhao299/phoenix-erp-v3/actions/runs/45715810289/job/139568077466)

## 一、问题与目标

现版侧栏「蛋品来源档案」和「产品档案」共用 `MENU_MD_PRODUCT`，角色面板按 `sys_menu` 中登记的「产品档案」显示。普通账号可通过旧码取得动作，但授权同时作用于产品业务。超管跳过菜单拦截，无法代替普通申请人与审核人的验收。目标是在「系统设置 → 角色与权限 → 主数据 → 蛋品来源档案」独立配置查看、申请与提交、审核，以及相应的组织和仓库范围。 [导航配置](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/web/src/components/layout/Sidebar.tsx#L240-L265) · [角色菜单数据源](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/api/src/modules/permissions/permissions.service.ts#L97-L122)

| 复审发现 | 修订决定 |
| --- | --- |
| 方法级 `E/A` 覆盖类级 `V`，直接调用 API 时只换菜单码仍会漏查 `V`。 | 写接口显式检查有效 `V+E` 或 `V+A`，覆盖两个预检及兼容预览。 |
| 角色窗口使用通用动作，角色保存全量重写时可能丢失已有拒绝与范围元数据，权限集也有独立保存路径。 | 新菜单的有效动作统一为 `V/E/A`。角色与权限集先验证，再按事务保存，保留其他项目的原授权元数据。 |
| 权限按三路来源合并，数据范围另按菜单读取用户的角色规则及组织绑定。只读角色的广范围可能被用于授权范围较窄的审核。 | 独立核验各用户的有效动作及其适用范围。审核和申请使用对应业务授权的范围，组合角色不能借用只读范围扩大写操作。 |
| 关联计划不可见时，现有详情隐藏原单，审批事务仍可能接受冻结摘要。候选仓与提交时的场站条件也不一致。 | 关联计划须在批准事务校验真实原单可读性。候选、预检及写入复用仓库判定。 |
| 强制重登后，待核操作可能只剩原请求号，浏览器不再有原请求正文。测试环境此前也替换了两个鉴权守卫。 | 切换前核清在途与待核结果，保留原回执机制。验收走真实角色注册、配置、登录、数据范围和 API。 |

## 二、授权和办理规则

新菜单码建议为 `MENU_MD_EGG_SOURCE`，显示名为「蛋品来源档案」，路径沿用 `/master-data/egg-sources`。沿用现有工作流动作位，申请岗命名说明预检、制单和提交的含义。

| 岗位 | 有效权限 | 可办理 |
| --- | --- | --- |
| 查阅 | `V` | 在授权范围内查档期、来源申请、详情和本人回执。 |
| 申请 | `V+E` | 预检、建草稿、提交及取消本人草稿或待审单，按现有状态规则申请撤销排期。 |
| 审核 | `V+A` | 独立批准或驳回，按现有状态规则批准或驳回撤销申请。 |

- 以正常实名账号办理。审核人须区别于该单的申请人和最近操作人。共同持有两类岗位权限的账号仍受逐单独立审核限制。本人权限、原单版本、原内容摘要、生效日、关联业务和正式库存域均在后端核验。代登录会话维持只读边界。 [原流程事务](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/api/src/modules/product-master/services/egg-source-change.service.ts#L269-L335)
- 使用已批准的组织和仓范围。核对角色直绑、角色权限集、用户权限集及显式拒绝。停用或隐藏角色、撤权或拒绝 `V` 时，有效写入应被拒绝，即使权限快照仍含单独的 `E/A`。现有范围解析会在角色集合中取最高范围。蛋源工作流须按有效动作对应的授权范围，与有效组织、仓范围取交集，范围来源无法确认时拒绝写入。优先复用现有服务并为本工作流补齐判定。普通账号的写入须使用能核对权限版本的会话。缺权限版本或快照落后时要求重新登录。 [角色和用户权限来源](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/api/src/auth/permission-sources.ts#L5-L51)
- 统一候选仓、预检、新建、提交、批准的判定。目标为所选鸡舍同公司、启用的操作仓，符合该场站或已允许的公司共享仓条件，且在实际仓授权内。现有 SITE 额外仓范围查询会排除空场站仓。东鹏目标仓归属需先核实，若是共享仓且标准授权路径无法覆盖，由业务决定安排已有合适范围的岗位或单列共享仓规则。 [候选仓](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/api/src/modules/product-master/services/egg-source-change-read.ts#L44-L58) · [SITE 仓范围](https://github.com/ivanzhao299/phoenix-erp-v3/blob/24ce3f0/apps/api/src/modules/org/services/data-scope.service.ts#L306-L340)

## 四、上线、验收与回退

1. **准备。** 业务负责人确认实际申请人、独立审核人、东鹏场站及目标仓，按当前角色、权限集和拒绝来源核对最终授权。运维保存变更前的授权及范围记录，业务负责人逐张核对将到期、已关联计划、待核审批回执和当前生效档期。权限管理员配置单列申请岗及审核岗。
2. **切换。** 在确认发布窗口、岗位名单及范围后，核清待回执及在途操作。受控迁移登记权限并同步暂停蛋源申请和审核。API 与 Web 切至同一目标提交，核实菜单注册表和角色页，再为已批准岗位配置授权及范围。普通用户退出并重新登录。旧产品权限不作为新接口的后备授权。旧标签页和额外 API 实例纳入切换验证。暂停只覆盖来源档案写操作，查单和回执按当前已核验版本及有效授权办理。
3. **验证后开放。** 先确认切换前已存在的待审单在新权限下正确显示、当前冻结信息一致，再由经授权的独立业务人员按实际单据办理。生产验收记录目标版本、菜单项读回、角色有效权限、实际仓范围及只读访问结果。同步发布手册中的权限入口和待审超期处理。
4. **回退。** 回退应用版本会恢复旧产品权限。需要回退时，先保持蛋源变更写入封闭，按已验证的回退路径恢复 API 与 Web 配对，核对新菜单登记、版本、原单和回执。开放写入前须确认独立鉴权仍有效；无法确认则保持暂停并采用前向修复。发布回退不批量撤销已提交的授权、档期、申请和入库事实。尚被角色或权限集引用的新目录条目保留，由授权记录单独清理。

| 验收场景 | 必须观察到的结果 |
| --- | --- |
| 真实配置链路 | 在隔离 PostgreSQL 注册、读取菜单、保存角色、指派用户、调用真实登录和守卫，与 Chromium 普通账号结果一致。V 只读，V+E 可办申请，V+A 可独立审核。 |

| 关联计划与业务回归 | 无计划可正常审批；有计划时校验目标舍及源舍，缺原计划查看权不能直接批准，驳回仍可用。冻结摘要、日期、版本或有效库存域变化时拒绝应用。测试原交易与审计完整。 |

| 旁路回归与发布 | 验证产品档案、历史蛋源核认、日产蛋入库、正式入库和原计划查询按各自权限可用。使用受控发布演练验证菜单登记、API/Web 配对和写入暂停及恢复。 |

## 六、实施及发布记录要求

### 角色与账号配置

1. 在「角色与权限」进入申请岗角色，找到「主数据中心 → 蛋品来源档案」，勾选「查看档案」「申请与提交」，选择核准的操作仓。
2. 在独立审核岗角色勾选「查看档案」「审核与驳回」，选择同一核准仓。使用权限集时可以按相同动作配成能力集，再绑定已批准的角色或用户。每个授予项保留自己的仓范围，账号还须具备覆盖该舍的组织授权及明确的仓授权。对关联鸡群原计划的批准，另核对「养殖数据」查看及实际源舍范围。
3. 回读角色或权限集的实际动作及目标仓，核对直绑、其他角色、权限集和显示及停用状态，再让两个账号重登。用现有真实单据只读核对可见鸡舍、目标仓和可办动作，按业务责任人指令处理真实待审单。
4. 未明确发起人、审核人及场站仓范围时，生产权限清单保持待核。生产单据按原流程查状态。待核页面可展示原请求号与已记录的发出时间，业务负责人核实回执及在途状态后处置。

### 受控切换

1. 先锁定审核通过的目标提交、现网 API/Web 版本、组织与仓、实名岗位人员名单和将到期待审清单。核对待核回执、正在处理的写入和独立 SKU 来源启用脚本。暂停后者直到切换完成。提前创建必要的专用角色和账号组织、仓库绑定。
2. 使用候选同一 SHA 的 Controlled Pending Migration Apply 检查待迁集合和账本。普通审核仅在实际 GO 后写入。目录登记与数据库写入保护同事务提交，**此处开始暂停蛋品来源新建、提交和审核**。先通知已确认窗口以及查单、回执的访问方式。旧 API 即使驻留也无法写入。历史蛋品来源核认继续走生产入库授权。正式发布平台切换容器时还有其通用排空阶段，应在同一维护窗口记录。
3. 迁移回执入账后，以同一提交成对发布 API 与 Web，手工发布输入 mode=full 和 run_migrations=false。核对逐实例菜单登记及两个镜像 SHA。依照前节为已批准角色配权、读回范围并安排重新登录。验证待审单、冻结信息、原回执及历史核认。记录版本、菜单、角色、人员、仓和验证时间。
4. 仅在上述证据齐备后，使用实际可见、有效的实名系统管理员会话调用 POST /api/sys/menu-registry/egg-source-write-control。请求根据已核实状态提供布尔 expectedEnabled、enabled，以及引用验收记录的 reason。记录实际返回的状态、时间和管理员。检查旧实例仍拒写，普通授权人员可以办理，关闭前后原回执可读。留存任何处置过的真实申请的原申请号和回执。

### 恢复与回退

- 使用相同写开关先暂停，再执行已批准的版本恢复或前向修复。写开关关闭等待已获共享锁的事务结束，进入过旧实例的操作由数据库保护。恢复旧应用后仍须保持来源变更暂停，使用新版本独立鉴权链验收后，才重新开放。
- SQL 迁移回退仅用于未开放且目录未被引用的环境。角色、权限集或数据范围引用和已开放记录都会阻止 down()。保留事实、授权记录与回执。迁移提交后若生产回执记录失败，保持关闭并按原候选重新核对物理迁移及现有回执。旧专项 egg-source-1125 对应另一批候选。

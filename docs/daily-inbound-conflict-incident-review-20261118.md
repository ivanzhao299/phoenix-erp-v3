## 3. 为什么会报这句话，已有记录又为什么仍在

### 3.1 具体拒绝路径

R 的 `ProductionInboundService.recordProductionInbound`：
1. :290-303 过滤数量为零的档位，本次形成六条正数请求。
2. :330-339 锁定日报维度，读取同公司、日期、鸡舍来源的所有 TEMP_PRODUCTION 批次；并非仅查这次 HTTP 请求，也不按客户端 source_no 筛选。
3. :350-355 要求每个请求档位恰有一条已有批次，再用已有批次的 **qty 当前余额**构造 actual。
4. :356-357 actual 与 expected 不同即抛出截图中的错误。
5. 只有没有已有批次，才到 :365-437 的来源/SKU/日报额度校验及创建循环；完全相同的请求则直接返回已有结果。

因此，该错误是在告知“已有业务来源与当前提交不一致”，没有承诺删除或回滚更早独立事务已经提交的数据。按此实现，若只有四级、五级两条记录，而其他六个请求档位不存在，会先触发另一句“档位或规格与已有记录不一致”。截图中特定错误与后来见到的全8档集合相符，不能只用两个错误批次解释全部条件。

R 的 :434 将 mgr 传给每次 createProductionBatch，:439 外层统一 ds.transaction；EggInventoryService :616-671 中批次和流水也使用该 mgr，没有逐档自行提交。若同一事务中后档失败，整体应回滚，符合 [PostgreSQL 事务原子性](https://www.postgresql.org/docs/18/tutorial-transactions.html)。已有真实 PG 用例也覆盖第二条流水故障整体回滚；本轮未重跑该 PG 用例。

## 4. 已确认的系统设计问题

### 4.1 预填剩余量，提交却要求已有整组完全相同

`FarmService.getEggsBreakdown` :554-565 用 SUM(inv_batches.qty) 读取已入数量，:618-628 用日报数减它，向页面返回剩余量。页面 `daily-inbound/page.tsx:100-105` 直接预填该返回值。

但提交服务 :334-375 只要有既有批次，就进入全量重放比较，不支持提交剩余量。首次入库额度只校验“不超过”，也允许低于日报的首批。这形成自相矛盾的业务契约：

**日报1,000 → 首批入100 → 页面预填900 → 提交服务拿900与已存在100比较 → 拒绝。**

它无需四、五级误录就能发生。本轮已用真实 FarmService 和 ProductionInboundService、模拟数据库返回值复现。

### 4.2 把现存量当原始过账量

- 重放比较：`production-inbound.service.ts:367` 使用 current qty。
- 剩余额度：同文件 :232-249 使用 SUM(qty)。
- 页面预填：`farm.service.ts:559,620` 也使用 current qty。
- 实际销售装车：R `egg-inventory.service.ts:1188-1200` 会扣减 qty。

因此“原入30，正常出库10，再重试原30”会报数量冲突。容量函数还会把消耗后的余额视为较小已入量；目前已有批次的严格冲突分支暂时挡住了普通补余，不能据此声称现 API 已经自动重复入库，但不能在增加分次功能时继续沿用该额度算法。

应当分开显示和计算：日报产量、原始入库量、经批准的更正量、累计有效生产过账量、当前库存、可用库存、实际出库量。销售和调拨不能重新产生“可入库产蛋额度”；退货也是库存流转，不能再计新产蛋。

### 4.3 单批创建旁路仍需封口

R `egg-inventory.controller.ts:97-115` / 候选 :110-127 的 `POST /api/v2/sales/inventory/batches` 直接转交 body 给 createProductionBatch，不经过日报整单编排。它仍有权限与来源/SKU校验，不是无权限任意写入；风险是日报额度和入库单约束不在统一服务边界。

该 body 是内联 TypeScript 类型，运行时元类型为 Object；`main.ts:87-93` 的全局 whitelist 不能据此推断额外字段一定会被剥离。本轮对实际 ValidationPipe 的 Object 元类型验证确认额外来源字段仍保留；**没有实际调用HTTP或证明成功绕过全部生产校验**。

方案应同时使用真实 DTO、服务端显式字段构造及服务层受控入口约束。普通单批接口不得通过传入 TEMP_PRODUCTION/PACKAGING 等字段绕过统一编排；内部包装和生产调用按既有来源治理进入统一写账，不能只加前端禁用按钮。

### 4.4 已有来源关系不等于整单提交凭证

候选中的 brd_egg_day_routes、brd_egg_source_receipts、inv_flock_source_links 分别记录入口模式、来源认领和鸡群/批次来源；它们有复用价值，但不是完整 HTTP 请求、分级明细和事务提交回执。不得把 source 字符串、库存 batchNo 或今日库存当成缺失的原始过账单。

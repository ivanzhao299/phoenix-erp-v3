# 蛋品来源档案按鸡舍管理

## 业务操作

新版申请以鸡舍为来源，从主数据带出公司、农场和场站。申请人填写生效日、商品壳色、等级与规格、变更依据，按实际情况关联原换群计划。预检展示匹配的 SKU 与交库准备状态。已有同壳色的旧批复可按原冻结的 SKU 组合和原换群计划发起接续。原计划的可见性继续遵循养殖计划权限。

申请人新建、预检并提交。另一名有审核权限的人员须在场站业务日到达生效日前审核。审核同时核对来源摘要和交库准备。仍走未切换流程的鸡舍可按该状态审核。存在与生效日冲突的切换草稿、正式范围暂停或产品开账证据缺失时，先处理对应的正式库存范围。重新打开详情可获取最新审核摘要。

实际收蛋、包装入库、正式入库和转换各自按已确立的实物交接、仓库与产品域执行。旧申请按照其原批准仓和原回执办理，旧单据入口仍可查看历史记录。

## 角色配置

系统管理员进入「系统设置中心 → 角色与权限」，打开目标角色，再进入「蛋品来源组织授权」。也可从「权限集」维护按相同范围复用的授权。可添加多行鸡舍、农场、场站或公司范围。系统以用户已有组织范围和该行授权的交集计算可操作鸡舍。

| 权限 | 业务动作 |
| --- | --- |
| V | 查看档案、来源申请及本人有权访问的回执 |
| C | 新建来源申请 |
| E | 操作本人草稿、提交、取消，按条件申请撤回 |
| A | 独立审核、驳回，按条件审核撤回 |
| D、X | 当前流程不开放 |

申请岗通常配置 V/C/E，独立审核岗通常配置 V/A。权限变更后用户重新登录。旧版权限矩阵下的目标仓仅用于旧版来源申请。权限集含新版授权时，由实名系统管理员管理绑定。配权记录进入系统审计。

## 发布及试点

受控迁移范围为 `egg-source-house-1126`。先检查已合并的精准候选、主分支 CI 和待迁项，取得官方检查回执。应用必须使用同一候选、检查运行号及两个摘要。DB 迁移以物理备份和完整解析为前提，只增加 `EggSourceHouseContract1795654800000`。后验必须确认 V1 开关与授权摘要、历史核对事实均一致，两个产品版本的数据库写入门禁有效，新版开关和试点范围默认关闭。API/Web 使用同一提交的正式镜像通过完整发布切换。

在确认旧 API 已完全退出生产流量、兼容 API/Web 均健康后，由系统管理员在角色列表进入「蛋品来源新版写入」与「鸡舍开通」，填写发布或试点依据。逐舍开通前核对独立申请、审核账号，按本舍实际情况核对是否属于正式范围。首次开通后，该舍的新建请求使用 V2。暂停某舍关闭该舍新建，已开通的 V2 单据仍可按新版全局开关办理。新版全局暂停保留历史查询。两个开关的实际可写性在申请页展示。

迁移已写入账本但耐久回执未写出时，受控流程使用原检查运行号、摘要和原应用运行号核对备份与账本，再补写回执。已经存在 V2 数据或开启记录时保留兼容 API，业务暂停通过写入门禁执行。

# 蛋品来源档案按鸡舍管理

## 业务操作

新版申请以鸡舍为来源，从主数据带出公司、农场和场站。申请人填写生效日、商品壳色、等级与规格、变更依据，按实际情况关联原换群计划。预检展示匹配的 SKU 与交库准备状态。已有同壳色的旧批复可按原冻结的 SKU 组合和原换群计划发起接续。原计划的可见性继续遵循养殖计划权限。

申请人新建、预检并提交。另一名有审核权限的人员须在场站业务日到达生效日前审核。审核同时核对来源摘要和交库准备。仍走未切换流程的鸡舍可按该状态审核。存在与生效日冲突的切换草稿、正式范围暂停或产品开账证据缺失时，先处理对应的正式库存范围。重新打开详情可获取最新审核摘要。

实际收蛋、包装入库、正式入库和转换各自按已确立的实物交接、仓库与产品域执行。旧申请按照其原批准仓和原回执办理，旧单据入口仍可查看历史记录。

## 角色配置

系统管理员进入「系统设置中心 → 角色与权限 → 权限矩阵」或「权限集」，在「主数据中心」找到「蛋品来源档案」。展开本行，按业务批准范围添加鸡舍、农场、场站或公司，可配置多行。保存时填写依据。角色直授和继承的权限集分别显示。生效范围为相应动作授权与账号实际养殖组织的交集。

| 权限 | 业务动作 |
| --- | --- |
| V | 查看档案、申请、详情及符合本人和当前查看范围的回执 |
| C | 预检新申请、保存草稿 |
| E | 预检、提交、取消本人符合条件的单据，按流程申请撤销授权范围内的排期 |
| A | 批准、驳回及处理撤销审核，审核人须独立 |
| D、X | 当前禁用 |

申请岗选择 V/C/E，独立审核岗选择 V/A。相关账号重新登录。在「新版鸡舍开放」输入两个实名岗位账号核对该鸡舍的实际动作。旧单办理区域记录旧权限与旧单使用的仓范围。编辑新版授权不会自动换算原仓授权。

## 发布及试点

受控迁移范围为 `egg-source-house-1126`。先检查已合并的精准候选、主分支 CI 和待迁项，取得官方检查回执。应用必须使用同一候选、检查运行号及两个摘要。DB 迁移以物理备份和完整解析为前提，只增加 `EggSourceHouseContract1795654800000`。后验必须确认 V1 开关与授权摘要、历史核对事实均一致，两个产品版本的数据库写入门禁有效，新版开关和试点范围默认关闭。API/Web 使用同一提交的正式镜像通过完整发布切换。

在确认旧 API 已完全退出生产流量、兼容 API/Web 均健康后，由系统管理员在角色列表进入「蛋品来源新版写入」与「鸡舍开通」，填写发布或试点依据。逐舍开通前核对独立申请、审核账号，按本舍实际情况核对是否属于正式范围。首次开通后，该舍的新建请求使用 V2。暂停某舍关闭该舍新建，已开通的 V2 单据仍可按新版全局开关办理。新版全局暂停保留历史查询。两个开关的实际可写性在申请页展示。

迁移已写入账本但耐久回执未写出时，受控流程使用原检查运行号、摘要和原应用运行号核对备份与账本，再补写回执。已经存在 V2 数据或开启记录时保留兼容 API，业务暂停通过写入门禁执行。

### 退出旧版新建

1. 受控检查和部署完成后，新门禁默认允许进入原过渡流程。系统管理员核对来源总写入、新版写入、公司来源档案切入、场站日历及两个岗位在同一鸡舍的有效权限，再填写依据开放该舍。
2. 在已审批的业务范围内办理第一份真实新版来源申请，由独立审核人审核。按业务清单逐舍登记开放或经批准的暂停，核对在途操作、临近生效的旧单与待核回执。
3. 系统管理员进入「角色与权限 → 旧版新建切换」，核对清单后填写依据并关闭旧版新建。这一步单向生效。未开通与暂停的鸡舍在普通入口显示原因，已提交的 V1 单据继续使用原授权。
4. 断网时用原账号和原请求号查回执。创建查回反映单据当前状态，动作查回反映原事件提交结果。一次未找到回执时保留待核，待权威确认原请求结束且未提交后再发起。
5. 停止新建某舍可用逐舍暂停。需要停止全部新版办理时使用新版全局开关。来源总写入开关同时影响两版。任何暂停后都应核对原回执。已经退出 V1 新建的环境继续使用兼容版本和保留新门禁的前向发布。

新增迁移使用独立的受控专项。常规审计仍保留历史差异结论，专项以候选源码、已核准的原历史事实、唯一新增迁移、备份和账本回执为约束。技术部署完成与真实岗位启用分别记录。

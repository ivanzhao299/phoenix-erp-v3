# Phoenix ERP 蛋鸡生产管理改造实施方案

**供生产、仓储、财务、研发和发布负责人评审。** 基线为 2026 年 11 月 23 日重新拉取的 `origin/main@6bb88544275dfef591cb96c0078f73e88496433b`。建议批准两批交付。第一批修正会影响存栏、交接、冲销和报表的业务规则，第二批按岗位整理 PC、手机及终端交互。两个批次可以在接口契约确定后并行开发，在同一试点候选上联合验收。软件交付和首舍实账启用分别签认。

本方案承接[上一轮评审](production-management-mvp-review-20261123.md)。已有证据包括 9 套 PostgreSQL 测试 203 项、Web 定向测试 46 项、6 个浏览器检查，以及 4 个已复现的异常。它们是改造前基线，本方案下列用例均须在候选版本重新验收。孟赛四、五级蛋各 30 枚保留为历史测试资料，试点只使用签认后的期初和真实新单。

## 二　统一事实和计算口径

| 业务问题 | 权威事实、单位与计算方式 |
|---|---|
| 某舍某日属于哪个群 | 使用有效占栏及过账单据。入栏日起生效，转舍当日由转入占栏承接后续日录，关群当日的最终产蛋仍归旧群。若当日先在旧舍发生死亡，死亡归其事件记录的原占栏。 |
| 有多少只鸡 | 单位为羽。逐占栏累计期初、入栏、转入、转出、死亡、淘汰、盘点及获准补偿。每次转舍两侧同量反向，已结束占栏余额为零，当前占栏余额与鸡群当前存栏一致。待售淘汰鸡有独立余额，实际交付不能再次扣在栏。 |
| 今天产了多少蛋 | 单位为枚。公司、鸡舍、产蛋日、班次唯一。整日与早晚班互斥。同一占栏的早晚产量可加，死淘按事件计一次。按日计算产蛋率时分母采用现有有效日末存栏口径，并标示口径。分母未知或为零时展示“无法计算”。料水缺测保留未知，部分班次有数据时标明“小计，另有班次未报”。 |
| 还可交多少 | 按日报来源分段和等级计算。**可交＝确认产量－普通入库已过账数量＋普通入库已过账冲销数量－原始收蛋已过账占用数量**。只在当前可信来源及允许的作业路径内展示该余额。按等级跨规格汇总。销售、包装消耗、处于审批中的冲销均不释放额度。 |
| 仓里还有多少 | 库存实存按公司、仓、批次和单位统计。可用与受限分别展示。当前实存、日报额度、原回执是三种事实，分别取数。原始收蛋记录进入转换前以其自身状态和数量展示，转换产出进入对应库存批次后计入实存。 |
| 如何识别产品 | 遗传品种属于鸡群档案，商业分类来自有效来源配置，等级和规格由主数据选择，SKU 由准入规则确定。分级数量、鸡群、来源和凭证在单据过账时绑定，追溯保留历史身份。 |

**对账例。** 同舍同档日报 1,000 枚，先交 100、销售 40、再交 900。此时已交净额 1,000、可交 0、该仓实存 960。第一次回执仍为 100。如果随后对符合冲销条件的原分段冲销 30 并过账，可交变为 30、实存变为 930。这个例子采用普通入库、无其他库存流动，其验收不依赖销售后仍能冲销已消耗的原批。

## 三　第一批开发工作

### A1　清舍、入栏与转舍

- 过账服务在既有舍锁下读取可追溯的最近关群或转出、清洗、验收单据和各自业务日。新占栏须满足“上次结束占用 → 清洗 → 验收 → 入栏或转入”的日期顺序，验收同日可在已完成验收后入栏，沿用同舍同日换群限制。校验事件日期、过账顺序与版本，不能仅看鸡舍当前显示 READY。没有可靠历史证据的旧舍进入盘点待核清单。
- 转舍在同一事务锁定源舍、目标舍及群，沿用稳定锁顺序、容量校验和配对事件。原单冲销在同一锁内追踪其占栏及之后已过账的转舍。数量变化影响已签交接时返回阻断原因、原单号及允许查看的转舍单号。非数量更正仍按既有审核办理。
- 当天有死淘再转舍时，按事件上的占栏归属汇总。日期粒度无法辨明产蛋来源时，沿用既有当日已录日报的转舍限制。仓储和养殖确认需要跨舍连带补偿时，另行定义与原转舍单关联的成对补偿、两舍复盘与独立审核。首期允许留待核实的差异单，禁止直接修改存栏投影消差。
- **验收**：11 日关闭、13 日清洗、14 日验收，12 日入栏及转入均被拒。14 日验收后合法入栏通过。旧舍 100、死亡 10、转 90 后冲销旧死亡被拦，两舍仍为 0 和 90。转舍与更正并发，至多一个操作按原版本成功。数据读写入口为鸡群生命周期服务及养殖日报汇总。[生命周期过账](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/farm/flock-lifecycle.service.ts#L407)

### A2　日报、分级与经营报表

- 正式日报创建、普通重试、批准更正、交接冻结和原始收蛋读取使用同一分级规则。建议为兼容现有调用方，在输入边界将十进制非负整数字符串规范为安全整数。拒绝空串、布尔、小数、负数、指数写法、超界值和未知码。新单按业务当时有效的必填库存档校验，显式 0 与缺档不同。已确认日报的等值重放按原记录语义返回原事实，不重写 JSON、版本或摘要，也不因主数据后来停用而改变旧回执。
- 已带交接、库存或回执的历史异常日报先只读列示。原摘要仍可验证时保留既存快照。无法与原证据核对时阻断新增认领，通过差异单修正。档位新增或停用时分别验证旧单找回和新单录入。已确认分级不能改到低于分段有效占用。
- 将班次产量和逐占栏死淘分别聚合，再按原事实归属和授权范围汇总。养殖日报、趋势、生产分析及相同口径的导出共用这两组结果。事件日没有产蛋日报仍展示死淘。日报缺失和确认零产分别展示。集团、公司、场站与鸡舍汇总须可从同一组明细重算。
- **验收**：早班 100、晚班 200、死亡 1。三处汇总显示 300 枚和 1 羽。有死淘无日报时显示产蛋未报。齐全档位中的字符串 “100” 保存为整数并可交库，漏填一个零档不能保存。已关联日报重传原值不改变交接摘要。[日报确认规则](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/farm/flock-lifecycle-daily.ts#L25) · [生产分析](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/analytics/services/production-analytics.service.ts#L14)

### A3　交接办结与关群

- 为关群和待办建立同一套“交接完成”判断。先用签认来源的日报、鸡群、占栏和业务日确定范围，再按交接身份分别核对普通入库单和原始收蛋单。合法路径恰有一份已过账事实即可认定该交接办结。无原据、双路同时认领、归属不明或仍有待办单时，返回可核查的原因和单号。
- 对未签或未过账作业展示待办，按实际状态办理签收、补交或经批准作废。关群还须满足原有的零存栏、最终班次/零产证明、健康及其他待办条件。关群与签收、过账共用舍和来源的并发控制。已结束占栏的旧单据不应误阻新群，归属不明确的旧单单独核定。
- **验收**：同一套真实 PG/HTTP 用例分别完成普通交库后关群、原始收蛋后关群。留一张确实未办结单则阻断并指出是哪张。原始收蛋只占一次额度，不能再用同一交接号走普通入库。[关群检查](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/farm/flock-lifecycle.service.ts#L536) · [原始收蛋](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/sales-v2/services/official-raw-collection.service.ts#L76)

### A4　原单冲销、账期和续制

- 在现有冲销下游检查中复用质检 JSON 批号识别逻辑。覆盖检查明细、失败明细、产品检验、不合格记录和已纳入的其他下游引用。质检负责人确认哪些状态可解除，待审、进行中、未知及有效失败引用一律待处理。质检登记与冲销都在同一批次锁协议中重新核对。结果只暴露操作者有权看到的引用或联系岗位。
- 对正向入库和冲销，按现行顺序锁定舍日、原分段、期间、批次，锁后复读余额、冻结摘要、证据以及原/当前期间版本。用数据库真实墙钟的 Asia/Singapore 日期做最终记账日守卫，参照现有原始收蛋和转换的延迟校验做法，覆盖最终写入到事务结束前的等待。预期日期变化则整单回滚。对已过账单的合法重试优先返回原回执。
- 提供“按原单续制”。建议用**取消旧冻结单＋生成关联的新草稿**的单一业务操作。保存前驱单号、请求意图、原交接身份和新版本，锁内再次判断旧单状态。重复请求返回同一后继。若竞争的过账先成功则返回原回执。旧意图和旧提交键永远定位旧单，新单使用新意图和冻结键。冲销原业务单据 ID 与续制前驱 ID 分开保存。冲销重新取当前的财务签认与业务审批。实物交接内容未变并能通过证据重验时复用原签收。来源、数量、接收人或证据变化时按既有规则重签。
- 底层沿用现有非取消交接唯一索引、提交键唯一和状态迁移约束。首期建议加一张只追加的单据续制关系表，以前驱、后继分别唯一，重试意图在公司内唯一，所有身份键非空。与取消、建草稿在同一事务写入。若现存其他表已可表达同等审计语义，可在 PR 评审中替代。普通续制要求具备取消及创建两项动作权限。岗位分离时允许有权人员从同一待办接续。不可从取消过的任意旧单重复派生新单。
- **验收**：月末两连接持锁跨午夜，普通入库及冲销均不生成旧日账。冻结、已审批、已过账三种旧单分别验证。并发续制、续制与过账竞争、响应丢失各只生成一个有效结果。成本未知和确认零成本在续制及审批后仍可区分。[冻结与取消](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/sales-v2/services/production-inbound-documents.service.ts#L485) · [冲销下游检查](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/sales-v2/services/production-inbound-documents.service.ts#L670) · [部分唯一索引](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/database/migrations/1794972000000-ProductionInboundDocuments.ts#L36)

### A5　来源关系与混批实存

- 复用库存批次、既有生产根关系和原始收蛋根关系，统一查询普通入库、调拨、拆批、包装、合并及实际转换的来源。按批次唯一身份统计仓库实存。一个批次经多条路径命中同一来源时去重。库存状态、可用量和实存量各自沿用既有口径。
- 返回“可明确归属的实存”“多来源关联批次”“该仓批次实存”三个视图。来源完整且全指向同一舍日、单位可核对时可计入明确归属量。跨舍日混合、旧档缺根或无法换算的行附原因。混批行展示整批数量和来源明细，同一整批不能再进入不同舍日的可加总列。查询与导出遵循同一口径，无法证明归属的量留空而非 0。
- 扩展余额响应采用可识别的口径版本，保留旧端找回已过账回执的格式。增设批次明细与分页。新 Web 读取新口径。若旧 Web 仍会将未知量显示为 0 或误加整批，则在过渡期间保持该试点关闭，待同版本切换后开放相关视图。
- **验收**：两个舍日分别投入 30、70，产出一批 100。仓库只算 100，两个来源均可反查该批，两舍明细均不声称本舍实存 100。另测仅由原始收蛋转换的批、同源拆后合、退回、损耗和受限库存。若业务要求按来源精确结算，再设计有单位的投入、产出、损耗和后续扣减分配明细，以及尾差策略。[额度及实存查询](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/sales-v2/services/production-inbound-documents.service.ts#L820) · [转换服务](https://github.com/ivanzhao299/phoenix-erp-v3/blob/6bb88544275dfef591cb96c0078f73e88496433b/apps/api/src/modules/sales-v2/services/official-inventory-conversion.service.ts#L128)

**试点观测。** 以公司、舍日、等级对账超额和重复过账，以批次对账库存重复和未知来源，以占栏对账期末残余，以任务跟踪待签收、结果待确认和续制冲突。区分提交被正确拦截与错误已经落账。告警给出范围、原单号和核验入口。场长负责业务差异，仓管负责实物和来源，财务负责期间与成本，发布负责人负责版本与技术恢复。首次交接、第二次交接和首日日结分别签核。
